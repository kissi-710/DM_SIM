# DM_SIM — デュエル・マスターズ シミュレータ(ブラウザ版)

デュエル・マスターズをブラウザで遊べるシミュレータです。**CPU対戦**・**CPU同士の観戦**・**確率シミュレータ**(確率調査・パターン調査)・**AI同士のバッチ対戦**を備えています。

- 対象カード: スターターデッキ DM26-SD1「25の王道」の2デッキ(マルル / 5cザーディ)の**全28種**と、追加デッキ「インターステラ型マルル」の新規4種(docs/decks.md 第8章)。効果・タイミング処理は汎用エンジンで実装しています。
- 設計・仕様: [docs/](./docs/)(overview / spec / design / effects / decks)。進捗: [ROADMAP.md](./ROADMAP.md)。
- 画像はありません(テキストのみ)。データに任意項目 `image` を足すと表示されます。

## 起動

Node.js(現行LTS以上。開発では v24 で確認)と npm が必要です。

```bash
npm install
npm run dev        # 開発サーバー(http://localhost:5173)
npm run build      # 型チェック + ビルド(dist/)
npm run preview    # ビルド結果の確認
npm test           # Vitest(ルール・全28種のカード・AI・シミュレータ)
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint
```

公開する場合は、`DM_SIM_BASE=/DM_SIM/ npm run build` のように `base` を公開パスに合わせます(既定は相対パス `./`)。`dist/` をそのまま静的ホスティングに置けます。(Windows の Git Bash では、パスが書き換わるので `MSYS_NO_PATHCONV=1` を先頭に付けてください。)

## 画面と操作

| 画面 | 内容 |
|---|---|
| CPUと対戦 | 人間 vs CPU。座席ごとに人間/CPU(ランダム・ルールベース・モンテカルロ探索)、情報条件(公平・部分開示・決め打ち・全開示)、先攻/後攻(ランダム・選択)、シードを選べる |
| CPU同士を観戦 | 速度調整・一時停止・「1手進める」 |
| 確率シミュレータ | 条件ビルダーで目標を組み立て、**確率調査**(達成率・95%信頼区間・累積グラフ・探索による上限・超幾何分布の検算)と**パターン調査**(達成する使用履歴・出現割合・絞り込み・履歴の再生・JSON/CSV出力) |
| バッチ対戦 | AI同士の数百〜数千試合。勝率(95%信頼区間)・先攻後攻別・情報条件の比較・カード単体の強さ |
| 棋譜の再生 | `{シード, デッキ, 先攻, 行動列}` から同じ試合を再現して1手ずつ確認 |
| 一人回し(手動) | 効果の自動処理なしで、カードを自由に動かして回す練習用 |
| デッキ編集 | 作成・保存(ブラウザ)・JSON入出力。対戦では40枚・同名4枚までを検査 |

### 対戦の操作

- **ドラッグ&ドロップ**: 手札 → マナゾーン(マナチャージ)/ 手札 → バトルゾーン(召喚・唱える)/ 自分のクリーチャー → 相手のクリーチャーまたはシールド(攻撃)/ 進化は重ねるクリーチャーの上へ。落とせる場所が緑で強調されます。
- **クリック代替**: カードをクリックすると、下のバーに「その札でできること」が出ます(スマホ対応を見据え、ホバー前提の操作はありません)。
- 効果の途中の選択(対象・選択肢・割り振り・順序・任意の確認)は、下部の入力ウィジェット(7種)で行います。同時に誘発した自分の能力の順序は、毎回選ぶか自動(左から)かを設定できます。
- 右の「待機中の能力」で、誘発して解決待ちの能力を確認できます。ログは因果ツリー(なぜ今これが起きたか)で、自動/手動のタグが付きます。
- 「1手戻す」(練習用設定)は、情報が公開された後や、CPUに手番が移った後には戻せません。

## CLI

```bash
# AI同士のバッチ対戦(同じ引数・同じコードなら同じ結果)
npm run batch -- --deckA maruru --deckB zardy --agentA rule --agentB random --games 1000 --seed 1
npm run batch -- --deckA maruru --deckB zardy --agentA rule --agentB rule --infoA partial --games 500
npm run batch -- --deckA maruru --deckB zardy --strength --games 300      # カード単体の強さ

# 確率調査・パターン調査
npm run prob -- --deck maruru --goal cost7-t4 --trials 300 --maxNodes 8000
npm run prob -- --deck maruru --goal mana5-t3 --mode patterns --trials 100 --out patterns.csv
```

目標のプリセット: `cost7-t4`(4ターン目にコスト7を使える)/ `cost7-t4-cast`(使った)/ `mana5-t3`(3ターン目までにマナ5枚以上)/ `opening-card`(初手に特定のカード)。JSONファイルでも指定できます(`--goal goal.json`)。

## 構成

```
src/
├─ engine/   純TypeScript(DOM・React・Worker に依存しない。ESLint で強制)
│   ├─ types / ast / registry   型・カード能力のAST・読み込み時の検証とコンパイル
│   ├─ engine / procs / vm      step(reducer)・手続きフレーム・効果インタプリタ
│   ├─ ops / derive / cond      原始操作・置換・派生ビュー・条件式
│   └─ legal / view / manual    合法手・PlayerView(情報条件)・手動操作
├─ cards/    カードデータ(JSON)とデッキプリセット
├─ ai/       random / rulebased / mcts / determinize
├─ sim/      batch(バッチ対戦)・solitaire(確率・パターン調査)・goal・strength
├─ workers/  ai.worker / sim.worker
├─ ui/       React 画面
└─ cli/      batch / prob
tests/       ルール・カード別シナリオ(28種)・台帳・AI・シミュレータ
```

設計の要点: 状態はJSON互換で `step(state, action)` は純粋関数。乱数は状態内のシード付きPRNG。カード能力はデータ(AST)で書き、バイトコードにコンパイルして再開可能な形で実行します。人間もAIも同じ `pending` と `Action` で操作します。

## 仮の仕様と制限

- ルールは総合ルール Ver.1.52 に基づきます。主な条文は原文(PDF)で照合済みですが、全体を網羅した照合ではありません(照合の範囲と未確認の項目は [docs/rules-reference.md](./docs/rules-reference.md) 12章と [ISSUES.md](./ISSUES.md))。不確かな点は [ROADMAP.md](./ROADMAP.md) の「要確認ルール台帳」(L1〜L10)に記録し、設定(`GameConfig`)で切り替えられる形にしてあります。
- 探索による上限は、ノード数の上限を超えたシャッフルを「未判定」として別に数えます(真の上限は「確認できた割合 〜 確認できた+未判定の割合」の範囲にあります)。
- ジャオウガの身代わりで破壊する3枚は、価値の低いカードから自動で選びます。
- オンライン対戦・スマホ向けレイアウト・上記28種以外のカードは対象外です。
