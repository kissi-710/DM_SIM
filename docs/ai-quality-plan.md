# モンテカルロ探索の「質」を上げる計画

Rust 版(WASM)で探索のラウンド評価が約6倍になった([ai-speed-and-strength.md](./ai-speed-and-strength.md) §3)。
速くなったぶんを「強さ」に変えるための計画と、その測り方・採否の基準をここに固定する。
実施結果は §6 に追記する(基準は結果を見る前に決めた)。進捗は [ROADMAP.md](../ROADMAP.md) の M7-18〜M7-21 が正。

## 1. 現状と、足りないもの

実装: [mcts.ts](../src/ai/mcts.ts)。決定化した世界ごとに、全候補手を同じ世界・同じ乱数で「1手指す → L1(ルールベース)の方針で3ターン先まで進める → 評価関数で報酬」し、劣る手を途中で外す(ペア比較)。

| # | 足りないもの | 根拠 |
|---|---|---|
| a | **物差しが粗い** | 勝率の測定は「ルールベースに勝つ率」だけ(80〜87%付近は天井に近い)。800試合で95%区間が約±2.5pt。小さな改善を検出できない |
| b | **頭打ちの原因が未特定** | 反復を倍にしても +1.75pt、60→120で +3.8pt。サンプル数ではなく、評価・方針・深さの偏りが上限を決めている疑いが強い |
| c | **評価関数が手作りの線形和** | 座標降下で効いたのはマナの重みだけ。特徴量が粗い(盤面のクリーチャーはパワー以外区別せず、S・トリガー、タップ状態、打点、カードごとの差を見ていない) |
| d | **木を作らない** | 候補手は「1手目」だけ。2手目以降は L1 任せなので、ターン内の行動の組合せ(順序・何を残すか)を評価できない。探索単体(上乗せ 0)は L1 より弱かった |

## 2. 方針(4段階。依存の順)

1. **物差し**(a): 感度が高く、結果が再現できる測定の道具を先に作る。
2. **ホライズンを「ゲーム終了まで」**(b): 評価関数を介さない純粋な勝敗でも探索できる。安く試せて、頭打ちの原因が「深さ」かが分かる。
3. **価値関数の学習**(c): 自己対戦のデータから、特徴量 → 勝率 を学習し、評価関数を置き換える。
4. **ターン内の行動列を木にする**(d): 自ターンの意思決定を木(決定化つき UCT)にする。

各段階の結果で、次の段階の優先度を見直す(段階2で「深さが原因」と分かれば、3・4の期待値が変わる)。

## 3. 物差し(段階1)

測定の道具は [src/cli/aiquality.ts](../src/cli/aiquality.ts)(`npx tsx src/cli/aiquality.ts --help`)。2種類を持つ。

### 3.1 新旧の直接対戦(`match`)

- A・B をどちらも設定文字列(`mcts:iter=120,horizon=3,w.mana=3.5` など)で指定する。同じ反復数・同じデッキの組・同じシードで、先攻後攻を入れ替えながら対戦する。
- 試合の分け方は **複製(duplicate)**: 同じシードの対局を、A の席を入れ替えて2回行う。同じデッキ同士では、配られる手札が同一になるので、運の差が打ち消される(組が違う時は、各席のデッキの並びが変わるので、複製にならない。席の入れ替えとシードの共有だけが効く)。
- デッキの組は、現在の全プリセット(maruru / zardy / lost-maruru)の全順列 9 組。
- 報告: A の勝率(引分は 0.5)と Wilson の95%区間、組ごとの勝率、1手あたりの平均探索時間。
- **用途**: 採否の最終判断(§5)。測っているのは「実際の対局での強さ」で、評価の偏りを含む。

### 3.2 教師との一致率(`teacher`)

- 局面の集合: ルールベース同士の対局(組・シードを固定)から、2択以上の意思決定を層化して抽出する(既定 300 局面。ターンで偏らないよう、ターン帯ごとに均等)。局面は**測るAIによらず同一**なので、設定間の比較に使える。
- 教師: 同じ局面(公平な情報条件の View)から、全候補手をペア比較で評価する。ホライズンはゲーム終了まで、ラウンド数は大きく(既定 400 ラウンド・外さない)。報酬は勝敗(1/0.5/0)なので、**手の価値 = 「その手のあと L1 で進めた時の勝率」**となり、意味が直接読める。教師の値は一度計算して、キャッシュ(`node_modules/.cache/dm-sim/`)に置く。
- 測るAI(設定文字列)の手を、その局面で選ばせ、次を出す:
  - **損失(regret)**: 教師の最善手の勝率 − 選んだ手の勝率(平均。勝率ポイント)。選択の質の中心の指標。
  - **一致率**: 教師の最善手と同じ手を選んだ割合。接戦(上位2手の差が 1pt 未満)の局面は別集計し、「接戦を除く一致率」も出す。
  - 手の種類別(マナチャージ / 召喚 / 攻撃 / 効果の選択)の損失。
- 勝率(§3.1)より**低ノイズ**: 1局面ごとに連続値の損失が出るので、300局面で、手の改善が数ポイントの損失の差として見える。
- **限界**(注記する): 教師は「L1 で続ける」前提の価値なので、L1 とは違う質の続け方(木・学習した価値)を採った AI の良い手を、不一致として罰することがある。ホライズンを変える実験(段階2)の採否にも使わない(教師と同じ深さの設定が有利になるため)。採否は §3.1 で決め、§3.2 は「どの種類の手が改善・悪化したか」の診断に使う。

### 3.3 速度の記録

どの測定にも「1手あたりの平均探索時間(ms)」「プレイアウト数」を併記する。速度の悪化を、強さの向上と相殺して判断する(同じ時間での比較も行う)。

## 4. 各段階の内容

### 4.1 段階2: ホライズンを「ゲーム終了まで」

- `horizon`(先読みターン数)を大きくすると、`rollout` はゲーム終了まで進め、報酬は勝敗(1/0.5/0)になる(評価関数・`tanh` の尺度を使わない)。コード変更は、プレイアウトの手数の上限(現在 400)を、終了まで足りる値にするだけ(TS・Rust 両方)。
- 測るもの: horizon = 3(現行) / 5 / 8 / 終了まで × 反復 120 / 480、上乗せ 0.005 / 0。**反復を増やした時に伸びるか**で、頭打ちの原因を切り分ける:
  - 深さ(評価の偏り)が原因なら、終了まで進めると、同じ反復で上がる。
  - ばらつき(プレイアウトの運)が原因なら、終了まで進めると下がり、反復を増やすと上がる。
- 速度: 1回のプレイアウトが長くなる。時間あたりの強さで比べる。

### 4.2 段階3: 価値関数の学習

- **特徴量**を増やす(プレイヤーごとに数え、差を取る): 盤面の数・パワー・ブロッカー(タップされていないもの)・攻撃可能な数と合計ブレイク数・スピードアタッカー・進化・シールド(0枚の危険を別特徴に)・手札(コスト帯・使える枚数)・マナ(区分線形)・墓地・山札・手番。さらに**カードごとの価値**(場・手札の defId 別の枚数)。
- **学習**: ルールベース同士(探索を弱くばらつかせた手を混ぜて、局面を多様にする)の自己対戦から、各ターンの開始時点の局面 → 最終の勝敗、を L2 正則化つきのロジスティック回帰で学習する。出力は勝率(0〜1)で、そのまま探索の報酬にする(`tanh` の尺度を要らなくする)。
- **保持**: 学習データ・特徴量・重みの生成は CLI(`src/cli/trainValue.ts`)で再現できる。重みは `src/ai/valueModel.json` に置く(小さい)。
- **二重実装**: 特徴量の計算を TS と Rust の両方に入れる。差分は、フィクスチャの局面で報酬が一致することをテストで固定する。
- **検証**: 保留したデータでの対数損失(旧評価をロジスティック変換したものと比較)→ 実戦(§3.1)。デッキ(カードプール)が3種なので、過学習を避けるため、(i) 正則化の強さを保留で選ぶ、(ii) 1デッキを抜いて学習し、そのデッキで測る(汎化の確認)、を行う。

### 4.3 段階4: ターン内の行動列を木にする

- 自分のターンの意思決定(ターン中の行動と、そのターンに自分が答える質問)を木にする。**決定化つき UCT(単一観測者 ISMCTS)**: 1回の反復ごとに世界を1つ決定化し、その世界で合法な辺だけを使って、UCB で下り、未展開の手を1つ展開し、プレイアウト(L1 の方針・ホライズンまで)で報酬を得て、経路に逆伝播する。
- ターンの終わり(ターン番号が変わる)で木を打ち切り、そこから先はプレイアウト。木の根の手の選び方は、訪問回数(外れ値に強い)。L1 の手を事前の候補(最初に展開・小さな上乗せ)として使う。
- 実装は、TS(基準)と Rust(速度)の両方。反復回数指定で、TS と Rust の結果が(浮動小数点の最下位ビットを除いて)一致するようにする(差分テスト)。
- 並列: 根の並列(Worker ごとに別の木・別の種で反復し、根の統計を足す)。反復数指定の再現性は、並列数が同じ時に保証する。
- 平坦なペア比較は、世界のばらつきを打ち消す点で優れている(M7-14)。木の側でも、同じ世界の中で子の比較をするため、**ラウンド = 世界1つ + 木を1反復ずつ**ではなく、候補(根の子)ごとの報酬のペア差を統計に取る補助を検討する。段階4の最初の版は、木の標準の UCB で行い、平坦版に対して測る。

## 5. 採否の基準(結果を見る前に固定)

既定の AI を置き換えるのは、次をすべて満たす時だけ。

1. **対戦(§3.1)**: 旧(現行の既定)に対して、同じ反復数で、**9組・合計 2,000 試合以上**、勝率の Wilson 95%区間の下限が 50% を超える。
2. **保留の確認**: 設定の調整に使わないシードで、同じ結論になる(調整と確認でシードを分ける)。
3. **ルールベースに対して**: 悪化しない(区間が旧と重なるか、上)。
4. **速度**: 同じ反復数の探索時間が +50% 以内、または、同じ時間(反復を調整)でも、旧に対して区間の下限が 50% を超える。
5. テスト(型・単体・Rust の差分)が通る。

条件を満たさなかった案は、**既定にせず**、設定(`AiTuning`)として残すか、結果だけを記録して取り下げる。測定の結果は、有意でなくても §6 に残す。

## 6. 結果

(段階ごとに追記する)

### 6.1 段階1: 物差し(実施: 2026-10)

実装: [aiquality.ts](../src/cli/aiquality.ts)(`match` / `teacher`)、[aiEval.ts](../src/sim/aiEval.ts)、複製対局(`FirstMode` の `duplicate`、`src/sim/batch.ts`)。テスト: `tests/sim/aiquality.test.ts`。
プレイアウトの手数の上限を 400 → 4000 にした(ゲーム終了まで進める設定でも足りる値。TS・Rust 両方。`MAX_ROLLOUT_STEPS`)。

**教師との一致率の識別力**(局面 600・教師 600 ラウンド・ゲーム終了まで。全 3 デッキの 9 組。約1分):

| 測るAI | 損失(pt) | 一致 | 接戦を除く一致 | 1手 |
|---|---|---|---|---|
| ランダム | 4.49(±0.35) | 53.7% | 33.7% | 0ms |
| ルールベース | 2.01(±0.18) | 63.5% | 48.5% | 0ms |
| mcts 反復30 | 1.26(±0.17) | 71.0% | 63.3% | 3ms |
| mcts 反復120 | 0.98(±0.11) | 71.7% | 66.3% | 7ms |
| mcts 反復480 | 0.88(±0.10) | 73.0% | 65.6% | 20ms |
| mcts 反復120・終了まで | 1.14(±0.12) | 72.0% | 66.3% | 30ms |
| mcts 反復480・終了まで | 0.57(±0.07) | 78.7% | 75.9% | 102ms |

- ランダム → ルール → 探索の順に、損失が単調に下がり、区間が重ならない。**1分で、反復を 30 → 120 に増やした差(0.28pt)も検出できる**(旧来の対ルールベース勝率では 800 試合で区間が ±2.5pt)。
- 「反復」は**全候補手のプレイアウトの合計**なので、反復120 は、候補が12手なら約10ラウンド(世界10個)にすぎない。
- 教師と同じ深さ(ゲーム終了まで)の設定が有利になる(0.57pt)のは、§3.2 の限界のとおり。深さを変える実験の採否には、直接対戦を使う。

**直接対戦の基準値**(9組 × 200試合 = 1800 試合、seed 1、複製対局): mcts 反復120 対 ルールベース **86.4%**(95%区間 84.8〜87.9)、1手 8.8ms。

### 6.2 段階2: ホライズンを「ゲーム終了まで」(実施: 2026-10)

条件: 9組 × 200試合(複製対局、seed 1)。A の設定を、B = `mcts:iter=120`(ホライズン3・上乗せ 0.005)と対戦。1手の時間は、この PC の 8 並列での平均。

| A(B は iter=120・h=3) | A の勝ち(95%区間) | 1手 A / B |
|---|---|---|
| iter=120, h=5 | 45.6%(43.3〜47.9) | 22.7 / 15.4ms |
| iter=120, h=8 | 37.3%(35.1〜39.5) | 36.4 / 18.2ms |
| iter=120, h=99(ゲーム終了まで) | **35.9%**(33.8〜38.2) | 24.5 / 9.3ms |
| iter=480, h=3 | 56.0%(53.7〜58.3) | 43.5 / 13.8ms |
| iter=480, h=99 | 51.4%(49.1〜53.7) | 124 / 13.5ms |
| **同じ時間**: iter=480, h=99 対 iter=1400, h=3(9組×100、seed 2) | **42.2%**(39.0〜45.5) | 150 / 116ms |

**結論: ホライズンを深くしても強くならない。むしろ弱くなる**(3ターン以上は単調に悪化。ゲーム終了まで進めると、同じ反復で 35.9%)。

- 原因は、深さではなく**続きの方針の質**と**ばらつき**。終了まで進めた報酬は 1/0 の勝敗で、120反復は約10世界にしかならず、手の差に対して分散が大きすぎる。反復を4倍にすると 35.9% → 51.4% まで戻る(深い設定は反復で伸びが大きい: +15.5pt。浅い設定は +6pt)が、**同じ時間で比べると浅い方が強い**(42.2%)。
- 先読みの先(2〜3ターン後)は、L1(ルールベース)が自分の手も代わりに指す前提の値になる。L1 は探索より弱いので、先へ進むほど、見積もりが「L1 の弱い手で進めた場合」に引っ張られる。手作りの評価(マナの重み 3.5 など)は、そのずれを補う役割を果たしている。
- 教師との損失(§6.1)は、ホライズン99の設定ほど小さくなる(反復480・終了まで 0.57pt)が、**実戦では弱い**。教師の価値(L1 で続けた時の勝率)は、強さの良い目標ではない。§3.2 の限界のとおり、採否は直接対戦で決める。
- 反復の増加は効くが、頭打ちが近い(120 → 480 で +6pt、120 → 1400 で +8.9pt(58.9%、9組×100試合、seed 11))。実際の CPU 戦(最大1.5秒の時間主導)では、Rust 版で 120 反復が約 7ms なので、早期終了がなければ数千〜2万反復まで回る(ここの 120 反復より強い設定で使われている)。

### 6.3 段階3: 価値関数の学習(実施: 2026-10)

**実装**: 特徴量 [valueModel.ts](../src/ai/valueModel.ts)(プレイヤーごとの 20 個の基本特徴量 + 手番 + バトルゾーン/手札のカード別の枚数)、学習 [valueTrain.ts](../src/sim/valueTrain.ts)・`src/cli/trainValue.ts`(自己対戦のターン開始局面 → 勝敗。L2 正則化つきロジスティック回帰、ニュートン法、対局単位で 20% を保留)。Rust 版(`rust/src/ai.rs` の `side_features` / `model_prob`)と、差分テスト(フィクスチャの 90 局面×4 シード、うち半分は価値関数・4つに1つはゲーム終了まで)で 1e-9 以内に一致。使い方: `aiquality` の設定に `value=<モデルJSON>`。

**予測の精度**(保留 20%、約 2.8 万局面。対数損失が小さいほど良い。何も知らない場合は 0.6931):

| 学習データ | 価値関数 | 手作りの評価(尺度だけ当てはめ) |
|---|---|---|
| ルールベース同士 12,000試合(13.8万局面・カード別あり) | **0.5765**(正解率 69.2%) | 0.6276(62.5%) |
| 同(カード別なし) | 0.5942(66.6%) | 0.6276(62.5%) |
| 探索(反復120)同士 6,000試合(6.7万局面) | 0.6126(64.8%) | 0.6560(58.0%) |

勝敗の予測としては、手作りの評価より明確に良い(終盤ほど差が大きい)。カード別の重みは、対数損失を 0.018 改善する。

**実戦**(9組 × 100試合、複製対局、seed 11、B = `mcts:iter=120` の手作りの評価):

| A | A の勝ち(95%区間) |
|---|---|
| ルールベース自己対戦で学習(カード別あり)、h=3 | 48.6%(45.3〜51.8) |
| 同(カード別なし) | 46.4%(43.2〜49.7) |
| 探索自己対戦で学習、h=3 | 49.0%(45.7〜52.3) |
| カード別あり、h=2 / h=4 / h=5 | 48.6% / 45.6% / **41.8%** |

**結論: 予測が良くなっても、探索の強さは上がらない**(区間はどれも 50% を含むか、下回る)。採否の基準(§5)を満たさないので、**既定にしない**(設定 `value=` で試せる opt-in として残す)。

- 評価関数の置き換えでは、強さの上限が動かない。これは、評価の重みの調整で効いたのがマナだけだった事実(§2)とも合う。手の選択を左右する差は、盤面の静的な価値ではなく、続きの方針(L1)の質にある。
- 学習したモデルで先読みを深くしても(h=4・5)、悪くなる。手作りの評価と同じ傾向で、深さを使うには**続きの方針**を良くする必要がある(§6.2)。
- したがって、次の段階は、価値関数ではなく、**ターン内の自分の行動列を探索で決める**(木。§4.3)方向が筋。

### 6.4 段階4: ターン内の行動列を木にする(実施: 2026-10)

**実装**: [tree.ts](../src/ai/tree.ts)(TS が基準)と `rust/src/ai.rs` の `Tree`(Rust)。差分テスト: `rust/tests/diff.rs`(`tree_matches_ts`・`paired_tree_matches_ts`)、`tests/wasm/engine.test.ts`。2方式を作った。

| 方式(`algo=`) | 内容 |
|---|---|
| `tree` | 標準の決定化つき UCT(ISMCTS)。反復ごとに世界を1つ決定化し、根から UCB で下る。木に入れるのは「自分が答える入力待ち」(ターン中の行動・そのターンの質問)。ターンが変わった所から先はプレイアウト |
| `ptree` | 根は従来どおり**ペア比較**(全候補手を同じ世界・同じ乱数で評価し、劣る手を外す)。各候補手の**下(2手目以降)だけ**を木にする。世界のばらつきを根で打ち消しつつ、ターンの残りの手を探索で選ぶ |

**結果**(B = 同じ反復数の平坦なモンテカルロ `flat`。9組、複製対局。1手の時間は A / B):

| A | 試合 | A の勝ち(95%区間) | 1手 |
|---|---|---|---|
| tree(c=0.3)、iter=300 | 900(seed 21) | **44.4%**(41.2〜47.7) | 46 / 32ms |
| ptree(c=0.3)、iter=300 | 900(seed 21) | 53.0%(49.7〜56.2) | 32 / 30ms |
| ptree(c=0.1)、iter=300 | 900(seed 21) | 54.0%(50.7〜57.2) | 31 / 30ms |
| ptree(c=0.1)、iter=300 | 1800(seed 31) | **54.2%**(51.9〜56.5) | 32 / 31ms |
| ptree(c=0.03)、iter=300 | 1800(seed 31) | 52.3%(50.0〜54.6) | 31 / 30ms |
| **ptree(c=0.1)、iter=300(保留・調整に使っていないシード)** | 1800(seed 41) | **54.1%**(51.8〜56.4) | 32 / 30ms |
| ptree(c=0.1)、iter=1400(B も iter=1400) | 900(seed 41) | **53.8%**(50.5〜57.0) | 109 / 108ms |
| ptree(c=0.1)、iter=120 対 ルールベース | 1800(seed 41) | 87.1%(85.5〜88.6) | 14 / 0.1ms |

(参考: flat、iter=120 対 ルールベースは 86.4%(seed 1)。)

- 差は、反復を増やしても保たれる(iter=1400 で 53.8%)。平坦な方式自体は、反復で頭打ちになる(iter=1400 対 iter=120 で 58.9%、480 では 56.0%)ので、同じ時間で上積みできる ptree の価値は、予算が大きいほど相対的に大きい。
- **標準の木(`tree`)は、平坦なペア比較より弱い**(44.4%)。ペア比較をやめると、手の差が、世界のばらつき(相手の手札・山札の並び)に埋もれて、同じ反復では判定の精度が落ちる。木の利点(続きの手の探索)より、根の比較の精度の方が効く。
- **ペア比較を根に残して、2手目以降だけ木にする(`ptree`)と、同じ反復・同じ時間で +4pt**(54.1%、保留のシードでも 51.8〜56.4%)。探索定数は小さい方が良く、c=0.1 が最良(0.03 は 52.3%、0.3 は 53.0%)。
- 採否の基準(§5)を満たす: ① 9組・1800試合 × 2シードで区間の下限が 50% 超(51.9% / 51.8%)、② 保留のシードで同じ、③ ルールベースに対して悪化しない(87.1%)、④ 速度は +4%。**ptree(c=0.1)を既定にした**(`DEFAULT_ALGO`、`DEFAULT_TREE_OPTS`)。`algo=flat` で従来の動作に戻せる。ゴールデンテストの MCTS の固定値を更新した。
- 並列: 対 CPU 戦の Worker は、`ptree` のラウンドを Worker ごとに別の木で評価する(根の並列)。結果は並列数・Worker への割り当てで変わりうる(反復数指定の再現は、1つの木で逐次に行う場合に保証する)。標準の `tree` は並列にしない。

## 7. L1(続きの方針)の改善の試み(実施: 2026-10。**採用なし**)

**実装**(既定の挙動は変えない): [l1params.ts](../src/ai/l1params.ts)(L1 の優先度・しきい値 23 個 + カード別の補正 `cardKeep` / `cardPlay`)、`rulebased.ts` を調整値つきにした。測定の設定は `l1.<名前>=値`(L1 そのもの)・`rl1.<名前>=値`(プレイアウトの L1)・`l1file=<json>`・`lookahead=1`。道具: `src/cli/tuneL1.ts`(自己対戦の座標降下)、`src/cli/trainL1.ts`(探索の手からカード別の補正を学習)、`scripts/l1-diff.ts`(探索と L1 の食い違いの診断)。

## 9. バッチ対戦の性能と精度(実施: 2026-10)

目標: バッチ対戦(`npm run batch` / UI のバッチ対戦 / `aiquality match`)の、**1試合あたりの時間**と、**同じ試合数での勝率の誤差**を改善する。10 種類以上の方法を試し、効いたものだけを採った。
測定: [bench-batch.ts](../scripts/bench-batch.ts)(1スレッドの試合/秒。勝敗の要約も出すので、速度の変更で結果が変わっていないことを確認できる)、[bench-accuracy.ts](../scripts/bench-accuracy.ts)(同じ設定を別シードで 30 回繰り返し、推定の SD・報告された区間の半幅・被覆率)。この PC は i7-13620H(P コア 6 + E コア 4)で、他のアプリの負荷もあるため、速度は**最速値**(5 回の最小)で比べた。

### 9.1 性能

| 試行 | 結果 | 判定 |
|---|---|---|
| WASM の高速なアロケータ(サイズクラス別の空きリスト。`rust/src/fastalloc.rs`) | mcts 1手(反復120 対 ルール、1スレッド): 206.6 → **137.2ms(-34%)**。勝敗・手は同一 | **採用** |

### 9.2 精度

| 試行 | 結果 | 判定 |
|---|---|---|
| 推定量の見直し(席で層化・複製対局はペア単位・引分 0.5)。`estimateRate` | 区間の**正しさ**が改善(複製対局のミラーで ±6.9pt → ±0.5pt。対称で結果が決まる場合)。推定の SD は変わらない(alternate 2.60 / random 3.26 / duplicate 3.44pt、R=30) | 採用 |
| 開始時の手札・山札の上・シールドで回帰調整(CUPED)の見込み | R² = 0.016〜0.022(席だけで 0.011〜0.013)。分散は 98% にしかならない | 取り下げ |
| 途中局面の価値関数の予測を制御変量にする(多段階) | ターン 3〜8 の ρ² = 0.013〜0.066(分散は 93〜99% に) | 取り下げ |
| `--precision`(区間が目標の幅になるまで続ける) | 差が大きい対戦は早く終わる(rule 対 random は 600 試合で ±1pt)。結果は一括実行と一致 | 採用 |
| 複製対局を CLI・UI から選べるようにする | ミラー(同じデッキ・同じ AI)の SD が 2.9pt → 0.0pt。**異なるデッキでは効かない**(SD 3.4pt。配りが別のカードになるため) | 採用(機能) |

**精度が試合数でしか上がらない原因**: 勝敗は、序盤の配り(R² 約 2%)や途中局面(ρ² 約 4〜7%)では説明できず、後半の確率的な展開とその時の手で決まる。そのため分散を減らす共変量が効かず、勝率の誤差は √(p(1−p)/n) で決まる。つまり、**精度を上げる実質の手段は、試合を速く回して試合数を増やすこと**(§9.1)と、必要な精度で止めること(`--precision`)。

## 11. 隠れた情報の価値と、公開情報からの推論(実施: 2026-10。実験ブランチ `exp/yobinion-inference`)

目的: 上級者のように、公開情報(ヨビニオンで山札の下に戻った札、墓地・マナ・山札に行った札、相手の行動)から、相手の隠れたカードを読めるか。まず、どの隠れ情報にどれだけの価値があるかを測り、次に読めそうな部分を統計的に調べた。

### 11.1 ヨビニオンで山札の下に戻った札
engine が `knownDeck` に記録し、`toPlayerView` が `hints.deckKnown` で並びを伏せて渡し、決定化(TS・Rust)がその枠に先に割り当てる(design 7.3)。対 `infer=0` の勝率は、マルルのミラー 1000 試合で 50.1%(区間 47.0〜53.2%)、マルル・ザーディ 1600 試合で 50.7%(48.3〜53.2%)。強さは測れる差が出なかった。(旧測定。4 デッキの全 16 組で測り直した結果は、3 つのシード合計 7200 試合で 50.5%(49.4〜51.7)。生データ: docs/data/ai-experiments-2026-10/yobinion-inference-results.txt)

### 11.2 情報の価値(対戦で測る)
A だけに情報を足して、公平な B と戦う(mcts 120 反復。4 デッキの全 16 組 × 200 試合 = 3200 試合。区間は ±1.7pt 前後)。`aiquality match --a "mcts:iter=120,info=<記号>"`。

| A に足した情報 | 記号 | 勝率 | 95%区間 |
|---|---|---|---|
| 相手の手札 | `oh` | 52.4% | 50.7〜54.2% |
| 相手のシールド | `os` | 52.2% | 50.5〜53.9% |
| 相手の山札(次のドロー) | `od` | 52.9% | 51.2〜54.6% |
| 自分のシールド | `ms` | 53.4% | 51.7〜55.2% |
| 自分の山札(次のドロー) | `md` | 51.9% | 50.1〜53.6% |
| 相手の手札+シールド | `oh+os` | 52.7% | 51.0〜54.4% |
| すべて(全開示) | `full` | 58.8% | 57.1〜60.5% |

- どの1種類も +2〜3pt で、区間が重なり、単独では優劣を言えない。全部を足すと +8.8pt で、足し算より大きい(情報同士が補い合う)。
- **デッキリストの知識**は、候補が 3 デッキなら差が出ない(リスト既知 対 未知で 51.0%、800 試合)。カード同士の関連を学ぶ必要は、今のカードプールでは薄い。
- 相手のデッキリストが既知なら、シールド・山札の中身は一様で、公開情報から読めるのは**相手が選んで持つ手札**だけ。手札を完全に見ても +2.4pt なので、手札を読む推論の上限はそこまで。

### 11.3 手札を読めるか(自己対戦のデータで測る)
`scripts/hand-infer-eval.ts`。ルールベース同士 4800 試合(4 デッキの全 16 組 × 300)で、各ターンの最初を観測点にした(48,404 点・68 万行)。1 行 = (観測点, 相手の手札にあるかもしれないカード)。基準は「未知のどの枠も手札になる確率は h/N」。モデルは、基準の対数オッズに特徴量を足したロジスティック回帰(観測点ごとに、期待枚数が手札の枚数になるよう切片をそろえる)。試合の 30% を検証に使う。

| 特徴量 | 1 枚あたり対数損失の改善 | 95%区間(試合でブートストラップ) | AUC |
|---|---|---|---|
| 属性(コスト・呪文・S・ブロッカー) | 1.71% | 1.56〜1.85% | 0.670 |
| + 出せたターン数 | 1.73% | 1.59〜1.87% | 0.671 |
| + 出せるのに残したマナ(全期間・直近・文明つき) | 2.61% | 2.44〜2.76% | 0.682 |
| 全特徴量 | 2.64% | 2.47〜2.79% | 0.682 |

- 較正は良い(予測 0.035 → 実測 0.024、0.34 → 0.341)。有意だが小さい。
- 効く手がかりは 2 つ。(1) 相手が持ち続けやすいカードの種類(高コスト・ブロッカー)。(2) 出せるマナを残したターンがあるカードは、手札にない。
- **注意**: この規則性は、相手がルールベース AI であることに依存する。人間の相手では成り立たない可能性が高い。

### 11.4 結論
- 手札を完全に見ても +2.4pt。読める割合が小さいので、手札を読むモデルを決定化に入れても、勝率の変化は +0.3pt 以下と見積もられる。3200 試合の標準誤差は約 0.9pt なので、測れない。**決定化には入れない**。
- シールド・山札の中身は、リストが既知なら誰にも読めない。公開情報の数え上げ(ヨビニオンの下の札など)で足りる。
- もし続けるなら、(1) 公開された札が山札の下に行く他の場合(墓地から唱えて下に置く札など)の記録、(2) リスト未知の設定で、候補デッキを見えた札で重みづけして選ぶ、(3) 相手の行動の尤度で世界を捨てる(粒子フィルタ)の順。(3) は重いので、人間の相手の手本データが取れてから。

## 12. L1 の方針改善: 手の価値(Q)への回帰(実施: 2026-10。実験ブランチ。**召喚の選択のみ有望、未採用**)

§7 の「次に試すなら」(ラベルではなく、候補ごとの評価値を目標にした回帰)を試した。L1 で続けた時の勝率(教師の手の価値 Q。ゲーム終了まで・200 ラウンド)を、手の特徴量(約 180 個。手の種類ごとのブロック + カード別)の線形モデルに回帰し、最も高い手を選ぶ方針にした。L1 を 1 回分だけ改善する方針改善(policy iteration)にあたる。

**道具**(`src/ai/l1learn.ts`、`scripts/l1q-*.ts`): `l1q-data.ts`(自己対戦の局面を集め、Q と特徴量を保存。並列)→ `l1q-fit.ts`(判断の種類ごとにリッジ回帰、保留 20% で損失)→ `l1q-match.ts`(学習した方針 対 L1 の複製対局。`DELTA`: L1 の手より予測が delta 以上良い時だけ替える保守的な選び方)。

**データ**: ルールベース同士の自己対戦の局面 11,554(ターン中の行動のみ。マナチャージ 4012 / 召喚 2355 / 攻撃・終了 5187)。

**保留の局面での損失**(教師の最善手との差。小さいほど良い):

| 判断 | L1 | 学習 |
|---|---|---|
| 召喚の選択 | 2.04pt | **0.99pt**(一致 67.7% → 75.4%) |
| 攻撃・ターン終了 | 0.84pt | 0.57pt |
| マナチャージ | 2.34pt | 2.35pt(変わらず) |

**実戦**(学習した方針のその判断だけを L1 に替えて、L1 と複製対局。4 デッキ 16 組 × 300 対 = 9600 試合):

| 替えた判断 | 勝率(95%区間) |
|---|---|
| 召喚の選択 | **53.7%**(52.7〜54.7) |
| 召喚の選択(学習データの 10% / 30%) | 53.4% / 54.0% |
| 召喚の選択 + `DELTA`=0.01 / 0.03 | 53.8% / 53.7% |
| 攻撃・ターン終了 | 47.1%(46.1〜48.1) |
| 攻撃(`DELTA`=0.01 / 0.03 / 0.06) | 47.9% / 48.7% / 49.4% |
| 攻撃(相手のシールド 5 枚以上の時だけ) | 48.9% |
| 召喚 + 攻撃 | 51.2% |
| マナチャージ(3200 試合) | 46.2% |

- **召喚の選択は L1 を +3.7pt 上回る**(区間の下限 52.7%)。学習データは 10% でも同じ強さで、**データを増やしても伸びない**(線形モデルの表現力が上限)。
- 攻撃は、保留の損失では良くなるのに、実戦で悪化する(相手のシールドが多い、勝ちから遠い局面でも)。教師の値の差が小さく、判断が連続して起こるため、L1 が続けると仮定した Q と、実際の連続した手の選び方がずれる、と考えている。保守的な選び方で悪化は小さくなるが、L1 を上回らない。
- マナチャージは、手の差が小さく、学習しても改善しない(L1 の手作りの重みが良い)。
- 損失(保留)が下がっても、実戦で勝てるとは限らない。採否は対戦で決める(§3.1)。

**未了**: 探索のプレイアウト(Rust)に学習した召喚の方針を入れた時の、探索全体の強さ。入れるには、特徴量とモデルを Rust に二重実装する必要がある(価値関数と同じ手順)。続ける場合は、(1) 召喚モデルを Rust に移して対 旧の探索で測る、(2) 新しい方針で局面を集め直して 2 回目の改善、(3) 攻撃は、勝ち確定の判定(L1 の `lethalNow`)を残して残りだけ学習、の順。

### 12.1 召喚モデルを探索のプレイアウト(Rust)に入れた結果

召喚の手だけを候補にして学習し直した(`l1q-fit.ts --only-play`)モデルを `src/ai/models/play-v1.json` に置いた。AI の設定は `pm=src/ai/models/play-v1.json`(L1 の事前の候補と、プレイアウト(TS・Rust)の両方に入る)。Rust 版は `rust/src/ai.rs` の `PlayModel` / `learned_play_score`。TS 版との一致は `tests/wasm/engine.test.ts`(1e-9)で固定した。

| 比較(A = `pm` あり、B = なし。複製対局、4 デッキの全 16 組) | A の勝ち(95%区間) | 1手 A / B |
|---|---|---|
| ルールベース同士(L1 だけ。9600 試合、seed 5) | 52.9%(51.9〜53.9) | |
| mcts 反復 300(1600 試合、seed 101) | 51.0%(48.6〜53.4) | 21.5 / 19.1ms |
| 同(seed 102) | 52.2%(49.7〜54.6) | 15.4 / 13.5ms |
| 同(seed 103) | 49.6%(47.2〜52.1) | 15.6 / 13.5ms |
| **反復 300 の 3 回の合計(4800 試合)** | **50.9%**(49.5〜52.3) | |
| mcts 反復 120(1600 試合、seed 104) | 52.8%(50.3〜55.2) | 7.7 / 6.7ms |
| **すべての合計(6400 試合)** | **51.4%**(50.2〜52.6) | 約 +14% |
| 対ルールベース(反復 120、1600 試合、seed 105): A / 旧 | 89.8% / 90.3% | |

- 探索に入れると、L1 だけの場合(+2.9〜3.7pt)より効果が薄まり、**約 +1.4pt**(区間の下限は 50.2% とぎりぎり)。反復 300 の 3 回だけでは区間が 50% をまたぐ。探索は自分の 1 手目と 2 手目以降を探索で選ぶので、プレイアウトの召喚の質が効くのは、その先の続きだけ、という理解。
- 1手あたり約 14% 遅くなる(特徴量の計算)。同じ時間で比べると、差はさらに小さい(反復の倍増で約 +2pt なので、14% で約 -0.4pt)。
- 対ルールベースは変わらない(89.8% 対 90.3%)。
- 採否の基準(§5)の 1 つ目(9 組以上・2000 試合以上で区間の下限 > 50%)は、合計では辛うじて満たすが、反復 300 の単独では満たさず、保留のシードの扱いも揃っていない。**既定にはしない**(`pm=` の opt-in として残す)。

## 13. 悪手の洗い出しと、マナチャージの先読み(実施: 2026-10。実験ブランチ。**採用なし**)

目的: 「生身のプレイヤーと気づかない強さ」に向けて、CPU の目立つ悪手を機械的に拾い、直せるか。

**道具**: `scripts/blunders.ts`(CPU 同士 mcts 反復 600 で 300 試合を打ち、すべての判断の直前の局面を、教師(ゲーム終了まで・300 ラウンド)で評価して損失を記録。並列)と `scripts/blunders-report.ts`(判断の種類・ターン帯別の集計と、損失の大きい手の一覧。`deckMin` 引数で、山札の少ない局面を除く)。

**結果**(300 試合・約 1.9 万判断。損失 = 教師の最善手の勝率 − 選んだ手の勝率):
- 平均損失 0.56pt。損失 10pt 以上の「悪手」は **1 試合あたり 0.54 件**(山札 8 枚以上の局面)。
- 悪手の 8 割近くは**終盤(9 ターン目以降)**。種類では**マナチャージ**が最大(悪手率 2.8%、悪手による損失の寄与の約 6 割)。次いでメインを終える/ターン終了(0.8%)、召喚・詠唱(0.7%)。
- **見かけの悪手に注意**: 損失の上位は、教師の「L1 で続ける」前提のために出た見かけの悪手だった。(1) 山札が 3 枚の局面で、L1 は引く呪文を打ち続けて山札切れで負けるが、実際の CPU は次のメインで自分で探索し、直接攻撃で勝てる(教師 0% 対 100%)。(2) 「メインを終える」は攻撃ステップに進むだけで、攻撃は次の判断でできるが、教師は L1 の続きなので攻撃しないと見積もる。この 2 種は悪手として数えない(山札切れは `deckMin` で除外。メイン終了は集計に残るが、中身は同じ artifact)。
- 残るのは、マナチャージで「どのカードを置くか」の食い違い(教師の最善とのずれ 30〜60pt の例が複数)。ただし教師は L1 で最後まで続けた勝率で、探索(3 ターン先 + 評価)とは見ている先が違い、教師が正しいとは限らない(§6.2 のとおり、教師の値は強さの良い目標ではない)。

**マナチャージだけ先読みを深くする**(`chh=<ターン数>`。`AiTuning.chargeHorizon`): B = 通常(`mcts:iter=300`)、16 組 × 100 試合 = 1600 試合・複製対局(seed 201)。

| A | A の勝ち(95%区間) | 1手 A / B |
|---|---|---|
| `chh=6` | 50.9%(48.4〜53.3) | 15.3 / 13.3ms |
| `chh=10` | 50.7%(48.3〜53.2) | 23.4 / 17.6ms |
| `chh=99`(ゲーム終了まで) | 51.4%(48.9〜53.8) | 18.7 / 13.0ms |
| 3 条件の合計(4800 試合) | 51.0%(49.6〜52.4) | +15〜+44% |

- どれも +1pt 前後で、区間が 50% をまたぐ。時間は +15%〜+44%。**採用しない**(`chh=` の opt-in として残す)。マナチャージの食い違いは、先読みの深さでは埋まらない。

**まとめ**: 機械的に拾える悪手は、教師の限界(L1 の続き)に左右され、真の悪手は 1 試合に 0.5 件未満で、直す手がかりは見つからなかった。これ以上は、**人の目**(どの手が「人間らしくない」か)が要る。次の案: CPU の手のレビュー表(局面と、CPU の手・他の候補を並べ、自然か不自然かを人が付ける)を作り、不自然と言われた手のパターンをルールで直す。

## 14. 履歴ベンチ: 現在の探索 AI を、過去の版と戦わせる(実施: 2026-10)

目的: 開発の履歴をたどり、現在の CPU が最初期のモンテカルロや直近の版より強くなっているかを、同じエンジン・同じルールで測る。

**方法**: 過去のコミットの `src/ai` を `scripts/legacy/<版>/` に取り出し(`bash scripts/legacy-extract.sh`。import の相対パスだけを書き換え、現在のエンジンの上で動かす。取り出したコピーは git の管理外)、`scripts/history-bench.ts` で現在と戦わせる。4 デッキの全 16 組、同じデッキの並びとシードで席を入れ替える複製対局。旧版は TS 版(基準の実装)で動き、現在だけ Rust 版(WASM)を使う。

| 版 | コミット | 内容 |
|---|---|---|
| v0 | `1987996` | 最初期の L2。決定化 + ランダム寄りのプレイアウト + UCB。4 ターン先 |
| v1 | `71db838` | L1 の手順でプレイアウト + L1 の手を事前の候補 + ペア比較 + マナの重みの調整 |
| v2 | `c326a74` | ptree(ターン内の行動列を木にする)の導入 |
| v3 | `8e230b3` | 報酬の軌跡平均 |
| 直近の main | `4b9ee70`(2026-10-17) | 今回の作業の前の main。現在のコードの `infer=0` と、8 試合で手の列が完全に一致することを確認し、速い WASM 版で測った |

**結果**(A = 現在の既定の探索。A の勝ち。区間は 95%):

| 相手 | 1 手 300 反復に揃える | 1 手 200ms に揃える |

| v0(最初期) | **94.7%**(93.1〜95.9。960 試合) | **96.5%**(94.4〜97.8。480 試合) |

| v3(軌跡平均) | 50.8%(47.7〜54.0) | 54.8%(50.3〜59.2) |
| 直近の main | 50.1%(48.4〜51.8。3200 試合) | |

1 手あたりの時間(反復を揃えた条件): 現在 13〜19ms、旧版 150〜216ms(旧版は TS 版)。

**読み方**
- 最初期からは大きく強くなった(95〜96%)。ペア比較・マナの重み(v1)、ptree(v2)、軌跡平均(v3)の各段階が、それぞれ有意に効いた(v1 → v2 → v3 と、現在に対する勝率が 63.0% → 59.6% → 50.8% と近づく)。
- **v3 以降(2026-10-15 以降)は、測れる差が出ていない**: 対 v3 で 50.8%、対 直近の main で 50.1%(3200 試合で区間 ±1.7pt)。ルールの修正・ルールベースの改良・Rust 版の高速化・ヨビニオンの推論などは、探索の強さの向上にはつながっていない。時間を揃えると、現在は v3 に 54.8% で、Rust 版の速さの分が出ている。
- つまり、この探索の枠組み(決定化 + L1 のプレイアウト + 手作りの評価)は、軌跡平均の時点でほぼ頭打ちになっている。以降の試行(§7〜§13)が、どれも数 pt 未満だったことと一致する。

**再現**: `bash scripts/legacy-extract.sh` のあと、`npx tsx scripts/history-bench.ts --a cur --b v0 --mode iter --n 300 --games 30 --seed 11`(`--mode time --n 200` で時間を揃える。`--b cur --bextra infer=0` で直近の main)。

計算量を増やした時の伸び(反復 300 → 1000 → 3000 → 10000)と、これまでの試みの総括は、[ai-strength-report.md](./ai-strength-report.md) にまとめた。

- 参考(UI の「演出中も考える」オプションの効果測定。2026-10-20): 強い設定(`strong=1`)を、最大 1200ms のまま使うと、通常に 57.8%(400 試合、区間 52.9〜62.5%。別の測定の 56.8% と合わせて約 57%)。最大 2000ms に延ばしても、上乗せは測れなかった(対 強い設定・1200ms で 51.0%)。詳細と生データは docs/ui-effects.md 4.2、docs/data/ui-fx-think-2026-10/。
