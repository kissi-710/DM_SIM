# モンテカルロ探索の「質」を上げる計画

Rust 版(WASM)で探索のラウンド評価が約6倍になった([ai-speed-and-strength.md](./ai-speed-and-strength.md) §3)。
速くなったぶんを「強さ」に変えるための計画と、その測り方・採否の基準をここに固定する。
実施結果は §6 に追記する(基準は結果を見る前に決めた)。進捗は [ROADMAP.md](../ROADMAP.md) の M7-18〜M7-21 が正。

## 1. 現状と、足りないもの

実装: [mcts.ts](../src/ai/mcts.ts)。決定化した世界ごとに、全候補手を同じ世界・同じ乱数で「1手指す → L1(ルールベース)の方針で3ターン先まで進める → 評価関数で報酬」し、劣る手を途中で外す(ペア比較)。

| # | 足りないもの | 根拠 |
|---|---|---|
| a | **物差しが粗い** | 勝率の測定は「ルールベースに勝つ率」だけ(80〜87%付近は天井に近い)。800試合で95%区間が約±2.5pt。小さな改善を検出できない |
| b | **頭打ちの原因が未特定** | 反復を倍にしても +1.75pt、60→120で +3.8pt。サンプル数ではなく、評価・方針・深さの偏りが上限を決めている疑いが強い |
| c | **評価関数が手作りの線形和** | 座標降下で効いたのはマナの重みだけ。特徴量が粗い(盤面のクリーチャーはパワー以外区別せず、S・トリガー、タップ状態、打点、カードごとの差を見ていない) |
| d | **木を作らない** | 候補手は「1手目」だけ。2手目以降は L1 任せなので、ターン内の行動の組合せ(順序・何を残すか)を評価できない。探索単体(上乗せ 0)は L1 より弱かった |

## 2. 方針(4段階。依存の順)

1. **物差し**(a): 感度が高く、結果が再現できる測定の道具を先に作る。
2. **ホライズンを「ゲーム終了まで」**(b): 評価関数を介さない純粋な勝敗でも探索できる。安く試せて、頭打ちの原因が「深さ」かが分かる。
3. **価値関数の学習**(c): 自己対戦のデータから、特徴量 → 勝率 を学習し、評価関数を置き換える。
4. **ターン内の行動列を木にする**(d): 自ターンの意思決定を木(決定化つき UCT)にする。

各段階の結果で、次の段階の優先度を見直す(段階2で「深さが原因」と分かれば、3・4の期待値が変わる)。

## 3. 物差し(段階1)

測定の道具は [src/cli/aiquality.ts](../src/cli/aiquality.ts)(`npx tsx src/cli/aiquality.ts --help`)。2種類を持つ。

### 3.1 新旧の直接対戦(`match`)

- A・B をどちらも設定文字列(`mcts:iter=120,horizon=3,w.mana=3.5` など)で指定する。同じ反復数・同じデッキの組・同じシードで、先攻後攻を入れ替えながら対戦する。
- 試合の分け方は **複製(duplicate)**: 同じシードの対局を、A の席を入れ替えて2回行う。同じデッキ同士では、配られる手札が同一になるので、運の差が打ち消される(組が違う時は、各席のデッキの並びが変わるので、複製にならない。席の入れ替えとシードの共有だけが効く)。
- デッキの組は、現在の全プリセット(maruru / zardy / lost-maruru)の全順列 9 組。
- 報告: A の勝率(引分は 0.5)と Wilson の95%区間、組ごとの勝率、1手あたりの平均探索時間。
- **用途**: 採否の最終判断(§5)。測っているのは「実際の対局での強さ」で、評価の偏りを含む。

### 3.2 教師との一致率(`teacher`)

- 局面の集合: ルールベース同士の対局(組・シードを固定)から、2択以上の意思決定を層化して抽出する(既定 300 局面。ターンで偏らないよう、ターン帯ごとに均等)。局面は**測るAIによらず同一**なので、設定間の比較に使える。
- 教師: 同じ局面(公平な情報条件の View)から、全候補手をペア比較で評価する。ホライズンはゲーム終了まで、ラウンド数は大きく(既定 400 ラウンド・外さない)。報酬は勝敗(1/0.5/0)なので、**手の価値 = 「その手のあと L1 で進めた時の勝率」**となり、意味が直接読める。教師の値は一度計算して、キャッシュ(`node_modules/.cache/dm-sim/`)に置く。
- 測るAI(設定文字列)の手を、その局面で選ばせ、次を出す:
  - **損失(regret)**: 教師の最善手の勝率 − 選んだ手の勝率(平均。勝率ポイント)。選択の質の中心の指標。
  - **一致率**: 教師の最善手と同じ手を選んだ割合。接戦(上位2手の差が 1pt 未満)の局面は別集計し、「接戦を除く一致率」も出す。
  - 手の種類別(マナチャージ / 召喚 / 攻撃 / 効果の選択)の損失。
- 勝率(§3.1)より**低ノイズ**: 1局面ごとに連続値の損失が出るので、300局面で、手の改善が数ポイントの損失の差として見える。
- **限界**(注記する): 教師は「L1 で続ける」前提の価値なので、L1 とは違う質の続け方(木・学習した価値)を採った AI の良い手を、不一致として罰することがある。ホライズンを変える実験(段階2)の採否にも使わない(教師と同じ深さの設定が有利になるため)。採否は §3.1 で決め、§3.2 は「どの種類の手が改善・悪化したか」の診断に使う。

### 3.3 速度の記録

どの測定にも「1手あたりの平均探索時間(ms)」「プレイアウト数」を併記する。速度の悪化を、強さの向上と相殺して判断する(同じ時間での比較も行う)。

## 4. 各段階の内容

### 4.1 段階2: ホライズンを「ゲーム終了まで」

- `horizon`(先読みターン数)を大きくすると、`rollout` はゲーム終了まで進め、報酬は勝敗(1/0.5/0)になる(評価関数・`tanh` の尺度を使わない)。コード変更は、プレイアウトの手数の上限(現在 400)を、終了まで足りる値にするだけ(TS・Rust 両方)。
- 測るもの: horizon = 3(現行) / 5 / 8 / 終了まで × 反復 120 / 480、上乗せ 0.005 / 0。**反復を増やした時に伸びるか**で、頭打ちの原因を切り分ける:
  - 深さ(評価の偏り)が原因なら、終了まで進めると、同じ反復で上がる。
  - ばらつき(プレイアウトの運)が原因なら、終了まで進めると下がり、反復を増やすと上がる。
- 速度: 1回のプレイアウトが長くなる。時間あたりの強さで比べる。

### 4.2 段階3: 価値関数の学習

- **特徴量**を増やす(プレイヤーごとに数え、差を取る): 盤面の数・パワー・ブロッカー(タップされていないもの)・攻撃可能な数と合計ブレイク数・スピードアタッカー・進化・シールド(0枚の危険を別特徴に)・手札(コスト帯・使える枚数)・マナ(区分線形)・墓地・山札・手番。さらに**カードごとの価値**(場・手札の defId 別の枚数)。
- **学習**: ルールベース同士(探索を弱くばらつかせた手を混ぜて、局面を多様にする)の自己対戦から、各ターンの開始時点の局面 → 最終の勝敗、を L2 正則化つきのロジスティック回帰で学習する。出力は勝率(0〜1)で、そのまま探索の報酬にする(`tanh` の尺度を要らなくする)。
- **保持**: 学習データ・特徴量・重みの生成は CLI(`src/cli/trainValue.ts`)で再現できる。重みは `src/ai/valueModel.json` に置く(小さい)。
- **二重実装**: 特徴量の計算を TS と Rust の両方に入れる。差分は、フィクスチャの局面で報酬が一致することをテストで固定する。
- **検証**: 保留したデータでの対数損失(旧評価をロジスティック変換したものと比較)→ 実戦(§3.1)。デッキ(カードプール)が3種なので、過学習を避けるため、(i) 正則化の強さを保留で選ぶ、(ii) 1デッキを抜いて学習し、そのデッキで測る(汎化の確認)、を行う。

### 4.3 段階4: ターン内の行動列を木にする

- 自分のターンの意思決定(ターン中の行動と、そのターンに自分が答える質問)を木にする。**決定化つき UCT(単一観測者 ISMCTS)**: 1回の反復ごとに世界を1つ決定化し、その世界で合法な辺だけを使って、UCB で下り、未展開の手を1つ展開し、プレイアウト(L1 の方針・ホライズンまで)で報酬を得て、経路に逆伝播する。
- ターンの終わり(ターン番号が変わる)で木を打ち切り、そこから先はプレイアウト。木の根の手の選び方は、訪問回数(外れ値に強い)。L1 の手を事前の候補(最初に展開・小さな上乗せ)として使う。
- 実装は、TS(基準)と Rust(速度)の両方。反復回数指定で、TS と Rust の結果が(浮動小数点の最下位ビットを除いて)一致するようにする(差分テスト)。
- 並列: 根の並列(Worker ごとに別の木・別の種で反復し、根の統計を足す)。反復数指定の再現性は、並列数が同じ時に保証する。
- 平坦なペア比較は、世界のばらつきを打ち消す点で優れている(M7-14)。木の側でも、同じ世界の中で子の比較をするため、**ラウンド = 世界1つ + 木を1反復ずつ**ではなく、候補(根の子)ごとの報酬のペア差を統計に取る補助を検討する。段階4の最初の版は、木の標準の UCB で行い、平坦版に対して測る。

## 5. 採否の基準(結果を見る前に固定)

既定の AI を置き換えるのは、次をすべて満たす時だけ。

1. **対戦(§3.1)**: 旧(現行の既定)に対して、同じ反復数で、**9組・合計 2,000 試合以上**、勝率の Wilson 95%区間の下限が 50% を超える。
2. **保留の確認**: 設定の調整に使わないシードで、同じ結論になる(調整と確認でシードを分ける)。
3. **ルールベースに対して**: 悪化しない(区間が旧と重なるか、上)。
4. **速度**: 同じ反復数の探索時間が +50% 以内、または、同じ時間(反復を調整)でも、旧に対して区間の下限が 50% を超える。
5. テスト(型・単体・Rust の差分)が通る。

条件を満たさなかった案は、**既定にせず**、設定(`AiTuning`)として残すか、結果だけを記録して取り下げる。測定の結果は、有意でなくても §6 に残す。

## 6. 結果

(段階ごとに追記する)

### 6.1 段階1: 物差し(実施: 2026-10)

実装: [aiquality.ts](../src/cli/aiquality.ts)(`match` / `teacher`)、[aiEval.ts](../src/sim/aiEval.ts)、複製対局(`FirstMode` の `duplicate`、`src/sim/batch.ts`)。テスト: `tests/sim/aiquality.test.ts`。
プレイアウトの手数の上限を 400 → 4000 にした(ゲーム終了まで進める設定でも足りる値。TS・Rust 両方。`MAX_ROLLOUT_STEPS`)。

**教師との一致率の識別力**(局面 600・教師 600 ラウンド・ゲーム終了まで。全 3 デッキの 9 組。約1分):

| 測るAI | 損失(pt) | 一致 | 接戦を除く一致 | 1手 |
|---|---|---|---|---|
| ランダム | 4.49(±0.35) | 53.7% | 33.7% | 0ms |
| ルールベース | 2.01(±0.18) | 63.5% | 48.5% | 0ms |
| mcts 反復30 | 1.26(±0.17) | 71.0% | 63.3% | 3ms |
| mcts 反復120 | 0.98(±0.11) | 71.7% | 66.3% | 7ms |
| mcts 反復480 | 0.88(±0.10) | 73.0% | 65.6% | 20ms |
| mcts 反復120・終了まで | 1.14(±0.12) | 72.0% | 66.3% | 30ms |
| mcts 反復480・終了まで | 0.57(±0.07) | 78.7% | 75.9% | 102ms |

- ランダム → ルール → 探索の順に、損失が単調に下がり、区間が重ならない。**1分で、反復を 30 → 120 に増やした差(0.28pt)も検出できる**(旧来の対ルールベース勝率では 800 試合で区間が ±2.5pt)。
- 「反復」は**全候補手のプレイアウトの合計**なので、反復120 は、候補が12手なら約10ラウンド(世界10個)にすぎない。
- 教師と同じ深さ(ゲーム終了まで)の設定が有利になる(0.57pt)のは、§3.2 の限界のとおり。深さを変える実験の採否には、直接対戦を使う。

**直接対戦の基準値**(9組 × 200試合 = 1800 試合、seed 1、複製対局): mcts 反復120 対 ルールベース **86.4%**(95%区間 84.8〜87.9)、1手 8.8ms。

### 6.2 段階2: ホライズンを「ゲーム終了まで」(実施: 2026-10)

条件: 9組 × 200試合(複製対局、seed 1)。A の設定を、B = `mcts:iter=120`(ホライズン3・上乗せ 0.005)と対戦。1手の時間は、この PC の 8 並列での平均。

| A(B は iter=120・h=3) | A の勝ち(95%区間) | 1手 A / B |
|---|---|---|
| iter=120, h=5 | 45.6%(43.3〜47.9) | 22.7 / 15.4ms |
| iter=120, h=8 | 37.3%(35.1〜39.5) | 36.4 / 18.2ms |
| iter=120, h=99(ゲーム終了まで) | **35.9%**(33.8〜38.2) | 24.5 / 9.3ms |
| iter=480, h=3 | 56.0%(53.7〜58.3) | 43.5 / 13.8ms |
| iter=480, h=99 | 51.4%(49.1〜53.7) | 124 / 13.5ms |
| **同じ時間**: iter=480, h=99 対 iter=1400, h=3(9組×100、seed 2) | **42.2%**(39.0〜45.5) | 150 / 116ms |

**結論: ホライズンを深くしても強くならない。むしろ弱くなる**(3ターン以上は単調に悪化。ゲーム終了まで進めると、同じ反復で 35.9%)。

- 原因は、深さではなく**続きの方針の質**と**ばらつき**。終了まで進めた報酬は 1/0 の勝敗で、120反復は約10世界にしかならず、手の差に対して分散が大きすぎる。反復を4倍にすると 35.9% → 51.4% まで戻る(深い設定は反復で伸びが大きい: +15.5pt。浅い設定は +6pt)が、**同じ時間で比べると浅い方が強い**(42.2%)。
- 先読みの先(2〜3ターン後)は、L1(ルールベース)が自分の手も代わりに指す前提の値になる。L1 は探索より弱いので、先へ進むほど、見積もりが「L1 の弱い手で進めた場合」に引っ張られる。手作りの評価(マナの重み 3.5 など)は、そのずれを補う役割を果たしている。
- 教師との損失(§6.1)は、ホライズン99の設定ほど小さくなる(反復480・終了まで 0.57pt)が、**実戦では弱い**。教師の価値(L1 で続けた時の勝率)は、強さの良い目標ではない。§3.2 の限界のとおり、採否は直接対戦で決める。
- 反復の増加は効く(120 → 480 で +6pt)。実際の CPU 戦(最大1.5秒の時間主導)では、Rust 版で 120 反復が約 7ms なので、早期終了がなければ数千〜2万反復まで回る(ここの 120 反復より強い設定で使われている)。

### 6.3 段階3: 価値関数の学習(実施: 2026-10)

**実装**: 特徴量 [valueModel.ts](../src/ai/valueModel.ts)(プレイヤーごとの 20 個の基本特徴量 + 手番 + バトルゾーン/手札のカード別の枚数)、学習 [valueTrain.ts](../src/sim/valueTrain.ts)・`src/cli/trainValue.ts`(自己対戦のターン開始局面 → 勝敗。L2 正則化つきロジスティック回帰、ニュートン法、対局単位で 20% を保留)。Rust 版(`rust/src/ai.rs` の `side_features` / `model_prob`)と、差分テスト(フィクスチャの 90 局面×4 シード、うち半分は価値関数・4つに1つはゲーム終了まで)で 1e-9 以内に一致。使い方: `aiquality` の設定に `value=<モデルJSON>`。

**予測の精度**(保留 20%、約 2.8 万局面。対数損失が小さいほど良い。何も知らない場合は 0.6931):

| 学習データ | 価値関数 | 手作りの評価(尺度だけ当てはめ) |
|---|---|---|
| ルールベース同士 12,000試合(13.8万局面・カード別あり) | **0.5765**(正解率 69.2%) | 0.6276(62.5%) |
| 同(カード別なし) | 0.5942(66.6%) | 0.6276(62.5%) |
| 探索(反復120)同士 6,000試合(6.7万局面) | 0.6126(64.8%) | 0.6560(58.0%) |

勝敗の予測としては、手作りの評価より明確に良い(終盤ほど差が大きい)。カード別の重みは、対数損失を 0.018 改善する。

**実戦**(9組 × 100試合、複製対局、seed 11、B = `mcts:iter=120` の手作りの評価):

| A | A の勝ち(95%区間) |
|---|---|
| ルールベース自己対戦で学習(カード別あり)、h=3 | 48.6%(45.3〜51.8) |
| 同(カード別なし) | 46.4%(43.2〜49.7) |
| 探索自己対戦で学習、h=3 | 49.0%(45.7〜52.3) |
| カード別あり、h=2 / h=4 / h=5 | 48.6% / 45.6% / **41.8%** |

**結論: 予測が良くなっても、探索の強さは上がらない**(区間はどれも 50% を含むか、下回る)。採否の基準(§5)を満たさないので、**既定にしない**(設定 `value=` で試せる opt-in として残す)。

- 評価関数の置き換えでは、強さの上限が動かない。これは、評価の重みの調整で効いたのがマナだけだった事実(§2)とも合う。手の選択を左右する差は、盤面の静的な価値ではなく、続きの方針(L1)の質にある。
- 学習したモデルで先読みを深くしても(h=4・5)、悪くなる。手作りの評価と同じ傾向で、深さを使うには**続きの方針**を良くする必要がある(§6.2)。
- したがって、次の段階は、価値関数ではなく、**ターン内の自分の行動列を探索で決める**(木。§4.3)方向が筋。
