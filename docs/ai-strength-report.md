# CPU を強くする試み: 試したことと結果(2026-10-17〜18)

「強い対戦相手が欲しい」「公開情報から相手の隠れた札を読むような、上級者の読みを入れられないか」という依頼から始めて、CPU(モンテカルロ探索)を強くするために試したことと、その結果をまとめる。
詳しい手順と表は [ai-quality-plan.md](./ai-quality-plan.md) の §11〜§14、生データは [data/ai-experiments-2026-10/](./data/ai-experiments-2026-10/) にある。

## 1. 要約

- **現在の CPU は、最初期のモンテカルロより大きく強い**(勝率 95〜96%)。ただし、その差のほとんどは、開発の初日(10/14〜10/15)の改善(ペア比較・L1 のプレイアウト・ptree・報酬の軌跡平均)で出たもの。
- **10/15 の軌跡平均の時点以降は、探索の強さに測れる改善が無い**。対 軌跡平均の版 50.8%、対 直近の main 50.1%(3200 試合)。
- 今回の試み(公開された札の推論、手札を読む学習、召喚方針の学習、先読みの調整、計算量の増加)は、**どれも +1〜3pt 以内**で、多くは区間が 50% をまたぐ。**既定にしたのは、ヨビニオンの山札の下の札の推論だけ**(強くはならないが、弱くならず、情報の扱いとして正しい)。他は設定(opt-in)として残したか、採用しなかった。
- **計算量を増やしても伸びない**: 1 手の反復を 300 → 1000 で +3.5pt、1000 → 3000 で +1.9pt、3000 → 10000 で +0.6pt。この探索の枠組み(決定化 + ルールベースのプレイアウト + 手作りの評価)は、ほぼ頭打ちになっている。
- 公開情報から読める隠れた情報は少ない(§4.2・§4.3)。相手のリストが分かっているとき、全開示で +8.8pt、そのうち相手の手札を完全に見ても +2.4pt。シールドと山札の中身は、誰にも読めない。
- 次に強くするには、**枠組みを変える**(プレイアウトの方針と評価を、大規模な自己対戦で学習し直す)か、勝率以外の目標(人間らしさ)を直接の目標にする必要がある(§6)。

## 2. 現在の強さ

### 2.1 過去の版との対戦(履歴ベンチ)

過去のコミットの探索 AI を、現在のエンジンの上で動かして、現在の既定の探索と複製対局(席を入れ替える)で戦わせた。4 デッキの全 16 組。数字は「現在」の勝率(95% 区間)。データ: `data/ai-experiments-2026-10/history/`。

| 相手(コミット) | 1 手 300 反復に揃える | 1 手 200ms に揃える |
|---|---|---|
| v0 最初期(`1987996`。ランダム寄りのプレイアウト + UCB) | **94.7%**(93.1〜95.9。960 試合) | **96.5%**(94.4〜97.8。480 試合) |
| v1 ペア比較・マナの重みの調整(`71db838`) | **63.0%**(59.9〜66.0。960) | **65.2%**(60.8〜69.3。480) |
| v2 ptree の導入(`c326a74`) | **59.6%**(56.4〜62.6。960) | **62.9%**(58.5〜67.1。480) |
| v3 軌跡平均(`8e230b3`) | 50.8%(47.7〜54.0。960) | 54.8%(50.3〜59.2。480) |
| 直近の main(`4b9ee70`。現在のコードの `infer=0` と手の列が 8 試合で一致) | 50.1%(48.4〜51.8。3200) | — |

- 旧版は TS 版(基準の実装)で動かしている。1 手あたりの時間は、反復を揃えた条件で、現在 13〜19ms、旧版 150〜216ms。
- 時間を揃えた条件で現在が少し強いのは、Rust 版(WASM)の速さの分。現在の探索は、早期終了があるため、200ms の枠のうち 20〜36ms しか使っていない。

### 2.2 計算量を増やした時の伸び

同じ現在の探索で、1 手の反復回数だけを変えて戦わせた(A が多い)。データ: `data/ai-experiments-2026-10/compute-scaling-results.txt`。

| A(反復) 対 B(反復) | A の勝ち(95% 区間) | 1 手 A / B |
|---|---|---|
| 1000 対 300 | 53.5%(50.4〜56.7。960 試合) | 31.6 / 12.5ms |
| 3000 対 300 | 52.6%(49.4〜55.7。960) | 61.5 / 12.8ms |
| 3000 対 1000 | 51.9%(48.7〜55.0。960) | 88.6 / 47.0ms |
| 10000 対 3000 | 50.6%(46.2〜55.1。480) | 108.6 / 59.9ms |

- 以前の記録(§6.2)では、反復 120 → 1400 で +8.9pt あったが、ptree と軌跡平均を入れた今は、300 → 1000 で +3.5pt、それ以降はほぼ伸びない。**サンプル数を増やしても上がらない**のは、探索の不確かさではなく、プレイアウトの方針(L1)と評価の質が、上限を決めているため。
- アプリの「思考時間」(最大 ms。既定 1200、最大 20000)を伸ばしても、強さはほとんど上がらない。

## 4. 各試みの要点

### 4.1 ヨビニオンの山札の下の札の推論

ヨビニオンで公開して山札の下に戻した札は、並びは分からないが、中身が両者に公開されている。engine が `GameState.knownDeck` に記録し、`toPlayerView` が `hints.deckKnown`(並びを伏せた多重集合)として渡し、決定化が、その札を先に山札の枠に割り当てる。残りの未知の札は、デッキリストからその分を引いた残りから選ぶ。「下にある札は引きにくい」「同名が 3 枚下にあれば、残る 1 枚の見込みは小さい」といった上級者の読みが、一様にシャッフルされたデッキの事後分布として出る。TS 版・Rust 版の両方に実装し、乱数の使い方を揃えて、差分テストで固定した。`infer=0` で切れる。

強さは測れなかった(7200 試合で 50.5%)。ヨビニオンが出る場面が少なく、出ても、探索の結果が変わる局面が少ないため。

### 4.2 隠れた情報の価値

A だけに情報を足して、公平な B と戦わせた(mcts 120 反復、16 組 × 200 = 3200 試合)。

| A に足した情報 | 勝率(95% 区間) |
|---|---|
| 相手の手札(`oh`) | 52.4%(50.7〜54.2) |
| 相手のシールド(`os`) | 52.2%(50.5〜53.9) |
| 相手の山札(`od`) | 52.9%(51.2〜54.6) |
| 自分のシールド(`ms`) | 53.4%(51.7〜55.2) |
| 自分の山札(`md`) | 51.9%(50.1〜53.6) |
| 相手の手札 + シールド(`oh+os`) | 52.7%(51.0〜54.4) |
| すべて(`full`) | 58.8%(57.1〜60.5) |

- どの 1 種類も +2〜3pt で、区間が重なり、優劣は付けられない。全部を足すと +8.8pt(足し算より大きい)。
- 相手のデッキリストが分かっているとき、シールドと山札の中身は一様で、誰にも読めない。読めるのは、相手が選んで持っている手札だけ。手札を完全に見ても +2.4pt なので、手札を読む推論の上限はそこまで。
- 補足(元データは保存していない。一時スクリプトの結果): 全開示 対 公平は、旧測定で 59.5%(800 試合)。相手のリストが既知か、候補 3 デッキから推定かの差は 51.0%(800 試合)で、差がなかった。

### 4.3 手札を読む学習

ルールベース同士 4800 試合(観測点 48,404、約 68 万行)のデータで、各ターンの最初に、相手の手札にありそうな札を、ロジスティック回帰で読めるかを測った。基準は「未知のどの枠も同じ確率」。検証は試合の 30%。

| 特徴量 | 1 枚あたりの対数損失の改善(95% 区間) | AUC |
|---|---|---|
| 属性(コスト・呪文・S・ブロッカー) | 1.71%(1.56〜1.85) | 0.670 |
| + 出せたターン数 | 1.73%(1.59〜1.87) | 0.671 |
| + 出せるのに残したマナ | 2.61%(2.44〜2.76) | 0.682 |
| 全特徴量 | 2.64%(2.47〜2.79) | 0.682 |

較正は良い(予測 0.035 → 実測 0.024、0.34 → 0.341)が、改善は小さい。効く手がかりは、相手が持ち続けやすい札の種類と、出せるのにマナを残したターンがある札は手札にない、という点。**相手がルールベース AI であることに依存した規則性**で、人間の相手では成り立たない可能性が高い。

### 4.4 L1 の方針の学習(召喚モデル)

L1 で続けた時の勝率(教師の手の価値 Q)を、手の特徴量(約 180 個)の線形モデルに回帰して、L1 を 1 回分だけ改善した(policy iteration)。教師データは、ルールベース同士の自己対戦の局面 11,554(ターン中の行動)。

| 判断 | 保留局面の損失 L1 → 学習 | L1 に対する実戦の勝率(9600 試合) |
|---|---|---|
| 召喚・詠唱の選択 | 2.04 → 0.99pt(一致 67.7% → 75.4%) | **53.7%**(52.7〜54.7) |
| 攻撃・ターン終了 | 0.84 → 0.57pt | 47.1%(46.1〜48.1)。悪化 |
| マナチャージ | 2.34 → 2.35pt(変わらず) | 46.2%(3200 試合)。悪化 |

損失が下がっても、実戦で勝てるとは限らない(攻撃)。召喚の選択だけが有望だったので、召喚の手だけを候補にした版(`src/ai/models/play-v1.json`)を、TS(L1・プレイアウト)と Rust に実装し、設定 `pm=` で使えるようにした。L1 同士(ルールベース)では 52.9%(51.9〜53.9)。

探索全体に入れると、効果は薄まった: 対 旧で **51.4%**(6400 試合、50.2〜52.6)、1 手の時間 +14%。探索は自分の 1 手目・2 手目を探索で選ぶので、プレイアウトの召喚の質が効くのは、その先の続きだけ、という理解。採用基準(複数のシードで区間の下限が 50% 超)を満たさないので、既定にはしていない。

### 4.5 悪手の洗い出しと、マナチャージの先読み

CPU 同士の 300 試合・約 1.9 万判断を、教師(ゲーム終了まで・300 ラウンド)で評価し、損失(教師の最善手の勝率 − 選んだ手の勝率)を集計した。

- 平均損失は 0.56pt。損失 10pt 以上の「悪手」は、1 試合あたり 0.54 件。8 割近くが終盤(9 ターン目以降)、種類ではマナチャージが最大(悪手率 2.8%)。
- 上位の悪手は、**教師が「L1 で続ける」前提のために出る見かけの悪手**だった。例: 山札が 3 枚の局面で、L1 は引く呪文を打ち続けて山札切れで負けるが、実際の CPU は次のメインで自分で探索し、直接攻撃で勝てる。「メインを終える」も、攻撃ステップに進むだけで、攻撃は次の判断でできる。
- マナチャージに残る食い違い(教師の最善とのずれ 30〜60pt)は、先読みの違い(CPU は 3 ターン先、教師はゲーム終了まで)の可能性があるので、マナチャージだけ先読みを深くしてみた(`chh=`)。6 / 10 / 99 ターンのどれも差が出なかった(合計 4800 試合で 51.0%、49.6〜52.4)。

### 4.6 CPU の手のレビュー表

CPU 同士の対局から 54 の判断(マナチャージ 14・召喚 12・攻撃/終了 16・効果の選択 12)を抜き出し、盤面・候補・CPU の手を並べて、自然か不自然かを人が付けられるページにした(Artifact として公開。評価は共有データベースの `reviews` に保存され、Claude が読める)。「生身のプレイヤーと気づかない強さ」には、勝率ではなく人の目の評価が要るため。評価は、まだ付いていない。

## 5. 測定の方法と限界

- **勝率**: 複製対局(同じデッキの並びとシードで、席を入れ替える)、4 デッキの全 16 組。区間は Wilson の 95%。1600 試合で ±2.4pt、3200 試合で ±1.7pt、9600 試合で ±1.0pt 程度。**区間が 50% をまたぐ結果は、差があるとは言えない**。
- **相手が同系統の AI**: ほとんどの測定は、CPU 同士の自己対戦。人間の相手に対する強さは測っていない。
- **教師の限界**: 教師の手の価値は「L1 で最後まで続けた時の勝率」で、探索(3 ターン先 + 評価)とは見ている先が違い、強さの良い目標ではない(§6.2)。損失が下がっても、実戦で勝てるとは限らない(攻撃の学習が例)。
- **デッキが 4 種類**: 学習・測定のデッキは、プリセット 4 種類だけ。別のデッキでは、結果が変わる可能性がある。
- **旧版の再現**: 旧版は、過去のコミットの `src/ai` を、import の相対パスだけ書き換えて、現在のエンジンの上で動かした(TS 版)。ルール・エンジンは現在のものなので、旧版は、旧ルールの下での強さではなく、「旧い探索アルゴリズムの強さ」を測っている。

## 5.1 通常の時間で指した試合の再検討(2026-10-19。実験ブランチ `exp/replay-analysis`)

CPU が通常の時間で指した試合を、あとで反復を大幅に増やして検討しなおし、「時間内に選べなかった良い手」があるかを調べた([ai-replay-analysis.md](./ai-replay-analysis.md))。

- 取りこぼしは存在する(食い違った判断の 14% で、深い探索の手が有意に良い。1 試合 1〜2 回)。通常の探索は、判断の 99.9% で早期終了し、反復の中央値 224 回しか使わない。
- 手を外す判定をなくし(`z=99`)、精度の基準を細かくした(`prec=0.003`)時間主導の探索は、通常の CPU に **56.8%**(960 試合)。1 手 675ms。反復 3000・`z=99` は 54.3%(1440 試合)、1 手 218〜267ms。
- ただし、負けた試合で見つけた大きな取りこぼし 8 件のうち、強い設定でも直るのは 1 件だけ。残りは、探索の見積もり(評価)の誤りで、時間では直らない。

## 6. 今後の方向

勝率の改善は、現在の枠組みの中ではほぼ頭打ち。続けるなら、次のいずれか。

1. **枠組みを変える**: プレイアウトの方針(L1)と評価を、手作りから、大規模な自己対戦で学習するものに替える(AlphaZero 型)。召喚の方針の学習は、その最小の試みで、効果はあったが(L1 同士 +3〜4pt)、探索全体では薄まった。方針と評価を一緒に、広い範囲(マナチャージ・攻撃を含む)で、繰り返し学習し直す必要があり、計算とデータの量が大きい。
2. **人間らしさを直接の目標にする**: §4.6 のレビュー表(または実際に遊んだ感想)から、不自然な手のパターンを拾い、ルールで直す。勝率は変わらない可能性が高いが、「生身のプレイヤーと気づかない」には、これが直接の測定になる。
3. **相手の行動から読む**: 相手の過去の行動の尤度で、世界(決定化)を絞る(粒子フィルタ)。上級者の「出せるのに出さなかった」という読みに近いが、計算が重く、人間の相手のデータが要る。
