## 目標(ユーザーの依頼・2026-10-23)

> カード効果について、もう一度確認し直して。非常に件数が多いですが、全てもう一度です。

> 確認して間違っている部分は修正して。
> **全て解決するまで行う。**

- 「最近追加された大量のカード」= 25の王道(DM26-SD1)の新規カード 243 種(デッキ C〜Y。`src/cards/defs/deck?.ts`)。最優先。
- 「全て」= 上に加えて、既存のカード(A マルル・B 5cザーディ・インターステラ型マルル・革命5cザーディ・ヨビニオン・基本のカード。`src/cards/data/cards.json`)も、最後に見直す。
- 完了の条件: 下の表の全項目にチェックがつき、見つけた誤りがすべて(修正+テスト+Rust 版への反映+コミット)済みであること。直せないルールの不明点は、ROADMAP の「要確認ルール台帳」に書いて、設定で切り替えられるようにする。

## 見るもの(1枚ごとの観点)

公式テキスト(`scratch/cardtext.txt`。git の管理外。**原文は文書・コミットに写さない**。要約か、カード名だけ書く)と、実装(`src/cards/defs/deck?.ts`)・テスト(`tests/cards/sd1-deck?.test.ts`)を、1枚ずつ突き合わせる。

1. **能力の欠落・余計な能力**: テキストにある能力がすべてあるか。ないものがないか(キーワード能力・S・トリガー・革命チェンジ・ブロッカー等も)。
2. **コスト・文明・種族・パワー・ブレイク数・種類**が合っているか(ツインパクトは両面)。
3. **タイミング**: 「出た時」「攻撃する時」「破壊された時」「ターン終了時」「〜する時、かわりに」の区別。誘発の種類(自分のターンだけ・相手のターンだけ)。
4. **対象・選択**: 「自分の/相手の」「バトルゾーン/墓地/手札」「1体/すべて/〜まで」「コスト・パワーの条件」。「まで」は 0 体でもよい。選べる枚数の上下限。
5. **「してもよい」と強制**: 任意のものが強制になっていないか。逆も。
6. **条件文**: 「そうしたら」「その後」「そのかわり」の前後関係(前の処理が空振りなら後ろは行わない、など)。
7. **持続**: 「このターン」「次の自分のターンのはじめまで」「バトルゾーンにある間」の期間。
8. **テストが、その能力を実際に固定しているか**(能力ごとに、成功と、条件を満たさない場合の両方。空振り・対象なし・選択肢が複数の場合)。
9. **AI・Rust 版でも同じに動くか**(エンジンを直したら Rust 版にも反映し、`npm run test:rust` と `scripts/diff-fuzz.ts` を通す)。

## 機械的な検査(人の目に加える)

- [ ] **A-1 全デッキの総当たり対局の不変条件検査**: 全25デッキ×全25デッキ(自分との対戦を含む)を、ルールベース・ランダムの AI で多数回対局させ、(a) エンジンの例外が出ない、(b) 必ず終局する(無限ループ・入力待ちの詰まりがない)、(c) カードが消えたり増えたりしない(ゾーンの合計が一定。GR・超次元などの別ゾーンを除く)、(d) 状態が JSON として往復できる、を確かめる。ずれた局面は `scratch/survey/` に書き出す(スクリプト: `scripts/audit-games.ts`)。

## 進め方の決まり

- 1デッキ(または 1 つの誤り)ごとにコミットする(CLAUDE.md)。誤りの修正にはテストを足す。テストで固定できないルールは台帳へ。
- エンジンを直した時は、Rust 版にも反映し、`npm run test:rust`・`scripts/diff-fuzz.ts`・`behavior-snapshot` を通す。**挙動を意図して変えた時だけ**、スナップショットを取り直す(理由をコミットメッセージに書く)。
- 公式のルール・裁定に迷ったら、推測で固定せず、総合ルール・公式 Q&A・DMwiki(二次出典と明記)で確かめる。
- 疑わしいが確証がないものは、「疑い」として本文書の記録に残し、確かめてから直す。
