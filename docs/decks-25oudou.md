# 25の王道(DM26-SD1)全25デッキのデッキリストと実装計画

- 作成日: 2026-10-22
- 目的: 商品「デュエル・マスターズ DM26-SD1 ドキドキつよいデッキ 25の王道」(2026-04-04発売。25種類のデッキのどれか1つがランダムで入っている)の**全25デッキ**を取得し、その**すべてのカードをシミュレータに実装する**(CPU対戦・確率調査で使えるようにする)。
- 実装済みの2デッキ: **A マルル**・**B 5cザーディ**([decks.md](./decks.md))。残りの**23デッキ(C〜Y)**が今回の対象。
- 関連: [decks.md](./decks.md) / [effects.md](./effects.md) / [ROADMAP.md](../ROADMAP.md)(M10)

## 取得元と信頼度

- 公式のデッキリスト(https://dm.takaratomy.co.jp/dm26sd1_decklist/deckNN/)は、当初メンテナンス中(HTTP 503)で取得できなかったが、**2026-10-22 のうちに取得できるようになり、25デッキすべての名前と収録カード・枚数を、実装(`src/cards/index.ts` のデッキ定義)と突き合わせた。完全に一致した**(表記の違いは全角/半角・波ダッシュの字形だけ)。
- **デッキ名は、公式のデッキ名をそのまま使う**(全角の「！」「＆」「４ｃ」なども公式のまま。通称は使わない)。N の正式名は「ジョーの一撃必殺**旅路**ジョーカーズデッキ」。
- 公式が取れなかった間は、次の二次出典で**照合**していた(CLAUDE.md の方針: 公式に加え、信頼できるサイトも使う。二次出典と明記する)。
  - **dmwiki**(https://www.dmwiki.net/DM26-SD1): 文明別に枚数つきで全デッキを載せる。主な出典。
  - **gachi-matome.com**(https://gachi-matome.com/p-dm-product-dm26-sd1/ と各デッキ記事 `…-sd1c/` 〜): カード解説の見出しの枚数。
  - **遊々亭**(https://yuyu-tei.jp/sell/dm/s/dm26sd1a 〜): デッキごとの収録カードの**種類数**(例: D は 13 種)。
- 照合の結果: 全23デッキが**40枚ちょうど**で、dmwiki と gachi-matome の枚数が一致した(例外は記事の抜けだけで、dmwiki を採用: F の決断は 2 枚、N のカツラデランスは 2 枚、K のハチ公は 9 枚)。◆(新規イラスト版)は同名として合算した。
- **GR・超次元・エクストラの別ゾーンは、どのデッキにも付属しない**(40枚の山札のみ。遊々亭の種類数とも一致)。
- 機械可読の版: [data/dm26sd1-decks.json](./data/dm26sd1-decks.json)(デッキID → 名前・`list: [カード名, 枚数]`)。

## 数

- デッキ: 25(実装済み 2 + 今回 23)
- 23デッキに現れる**異なるカード: 257 種類**(重複を除く)。うち実装済み(マルル・ザーディ・インターステラ等で既存): 14 種類、**未実装: 243 種類**。
- 名前に「/」があるカードは、ツインパクト(クリーチャー面 / 呪文面)。

## 実装の進め方

1. デッキごとに、未実装カードの**公式テキスト**を確認する(dmwiki 等。効果の要約は自分で書き、原文は写さない)。
2. 足りない**原始操作・タイミング・条件**があれば、エンジン(`src/engine`)に足す。足したら Rust 版(`rust/`)にも反映し、差分テスト(`npm run test:rust`)を通す。不確かなルールは ROADMAP の「要確認ルール台帳」に書く。
3. カードを `src/cards/data/cards.json` に定義し、`tests/cards/` にシナリオテストを書く。
4. `src/cards/index.ts` の `DECK_PRESETS` にデッキを足し、「全カード読み込み・40枚・同名4枚以下」の検証テストを通す。
5. デッキ単位でコミット(1コミット = 1つのまとまり)。進捗は ROADMAP の M10 に `[x]` を付ける。

## 実装メモ(簡略化・要確認の解釈)

全23デッキ(C〜Y)・257種類のカードを、2026-10-22 に実装した(ROADMAP M10)。デッキごとのカード定義は `src/cards/defs/deck?.ts`、テストは `tests/cards/sd1-deck?.test.ts`(S 以降は `sd1-deck-<小文字>.test.ts`。Windows ではファイル名の大文字小文字を区別しないため)。
全デッキの読み込み(40枚・同名4枚以下・全カードに能力あり)は `tests/cards/sd1-decks.test.ts` で確かめる。ルールの根拠は dmwiki など二次出典(公式サイトがメンテナンス中だったため)。

簡略化した点・解釈を選んだ点(変えたくなったら、ここを見る):

- **好きな順序で山札の下に置く**: 並びは、いまのままにする(メクレイド・「見る」効果すべて。並べ替えの選択はしない)。
- **「〜まで」「好きな数」の選択**: 上限までの枚数を選べる。0枚を選べる所は「使わない」で表す。
- **ガチンコ・ジャッジ**: 両者の山札の一番上を表向きにし、下に置く。コストが相手以上なら勝ち。山札が空の時は負ける扱い。
- **クロスギア**: ジェネレートは、手札から出す(コストを払う)。クロスは `CROSS` 行動で、**クロスギア自身のコストをもう一度払う**(dmwiki のクロスギアのルール)。クロスされたクリーチャーが離れると、クロスは外れて、クロスギアが残る。
- **超無限墓地進化(DOOM)・フシギバース**: 重ねる墓地のクリーチャーは、コストの大きいものから k 体(k を選ぶ)。フシギバースでマナゾーンに置く自分のクリーチャーは、アンタップしているものから選ぶ。
- **超七極 Gio**: 手札のコスト9の他のカードは、すべて見せたものとして、召喚コストを減らす。
- **ホールインワン・ヘラクレス**: タマシード/クリーチャーの二面性は簡略化し、常にクリーチャーとして扱う(攻撃できない条件だけ、自然のクリーチャー・タマシードが4つ未満の時に付く)。
- **水晶チャージャー**: 「裏向きにして」置く点は区別しない(マナゾーンのカードは裏向き)。
- **ニンジャ・チェンジ**: 入れ替えるクリーチャーが、攻撃先・ブロッカーだった時は、出たクリーチャーがその役を引き継ぐ。
- **ヴェネラック-F5**: 「相手のマナゾーンのカードをタップせずに」は、支払ったマナが0枚の召喚・出し方(`paid: 0`)で判定する。
- **清永**: 山札の上3枚のコストがすべて異ならない時は、何も起こらない(残りもマナゾーンに置かない)。
- **ハーデス オシオキムーン**: 自分のシールドゾーンを離れたカードすべて(ブレイク・身代わり・効果)で誘発する。
- **シェバ・エリクシア バラバラエティ5**: 自分のバトルゾーンのカードに、5つの文明がそろっていれば有効。
- **ダイハード・リュウセイ / ゲームに負ける時の置換**: 置換を選んでも、山札切れが続く場合は、次の状況起因処理でもう一度負けの判定をする。
- **ウルトラ・セイバー**: 置換で破壊するクリーチャーには、さらに置換を重ねない(同じ札が2枚で循環するのを避ける)。
- **ワールド・ブレイカー**: ブレイク数 98 として扱う。**G・ブレイカー**: ブレイク数 99 以上(その攻撃の後に、自分のシールドをすべてブレイクする)。
- **Rust 版(WASM)**: 全23デッキの新規カードを、Rust 版にも実装した(`RUST_READY_DECKS`)。探索のラウンド評価は、デッキごとの差分テスト(`npm run test:rust`)とランダムなデッキの差分ファジング(`scripts/diff-fuzz.ts`)で TS 版と一致を確かめてある。Rust 版にまだ無いカードを TS 版だけで先に足す時は、そのデッキを `RUST_READY_DECKS` に入れなければ、そのカードを含む対局の探索は TS 版で評価される(`TS_ONLY_CARD_IDS`)。
