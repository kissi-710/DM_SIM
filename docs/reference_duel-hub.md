## 1. サービスの概要(観察)

- 無料の**一人回し(プレイテスト)ツール**。デッキを読み込み、山札・手札・シールド・マナ・バトルゾーン・墓地のカードを**自分で動かして**回す。
- ほかに、myデッキ(保存・編集)、デッキ検索、商品情報、戦績、殿堂予想、初手埋め、AIカード検索、オフライン保存済みデッキ、日本語/英語切替、支援プラン(一部機能は有料)。
- 技術は Next.js 製の Web アプリ(観察: `/_next/static/...` と RSC 通信)。デッキはログインした本人のものが `/api/decks/<id>` で返る(観察: 未ログインでは404、ログイン後は200)。

## 2. UI構成

### 2.1 画面(観察: 狭い幅の表示)

上から順に、次の構成。

```
┌────────────────────────────────────────────┐
│ ヘッダー(ロゴ / 支援する / ユーザー名 / メニュー) │
├────────────────────────────────────────────┤
│ デッキのタブ ［1. 水闇自然マルル…］[保存][編集] [＋] │  ← 複数デッキを切り替えてプレイ
├────────────────────────────────────────────┤
│ [リセット]        [↶][↷][👁][🕘][⚙]         │  ← 元に戻す/やり直す/非公開領域の表示切替/履歴/設定
├──────────────────────────────┬─────────────┤
│ バトルゾーン      [∨][≡][↺]   │             │  ← ≡=ゾーン一覧 ↺=全アンタップ
├──────────────────────────────┤  山札(30)   │
│ シールドゾーン    [∨][≡]      │  ※クリックで │
│ (裏向きの札が横に並ぶ)        │   山札を表示  │
├──────────────────────────────┼─────────────┤
│ マナゾーン        [∨][≡][↺]   │  墓地        │
├──────────────────────────────┴─────────────┤
│              1ターン  [次のターン] [ドロー]    │
├────────────────────────────────────────────┤
│ 手札(カード画像が横に並ぶ)      [∨][≡]       │
└────────────────────────────────────────────┘
        (補助) カード拡大表示 / 操作履歴
```

- 「∨」は領域の折りたたみ、「≡」はゾーンの一覧(中身をすべて見る/並べ替える)、「↺」はそのゾーンの全アンタップ。
- ゾーンは**バトルゾーン、シールドゾーン、マナゾーン、山札、墓地、手札**の6つ。設定の「超GR」「超次元」で専用ゾーンを足せると思われる(推測)。
- 「1ターン」は**ターン番号の表示**、「次のターン」でターンを進める(自動でアンタップ・ドロー等を行うかは未確認)、「ドロー」で1枚引く。
- 初期状態は、山札シャッフル → シールド5枚をセット → 手札5枚。山札は30枚と表示(40−5−5)。

### 2.2 補助パネル(観察: アクセシビリティ情報)

- **カード拡大表示**: 「カードにマウスを乗せると拡大表示」。隠すボタンあり。→ 画像なしの DM_SIM では、**カードのテキスト全文を出すパネル**に当たる。
- **操作履歴**: 「ゲーム開始 [自動]: 山札をシャッフル・シールドをセット」のように、**ターンごとにまとまった一覧**。自動で行われた処理には「自動」のタグが付く。狭い幅ではダイアログ表示、広い幅ではパネル表示と思われる(推測)。

### 2.3 設定ダイアログ(観察)

| 項目 | 内容 |
|---|---|
| 直感(beta) | 切替(ON)。内容は未確認(カードを直接つかんで動かす操作のことかもしれない。推測) |
| **効果自動処理(beta)** | 切替(ON)。カード効果をツールが自動で処理するかどうか |
| **効果の処理結果を表示** | 切替(ON)。自動処理した結果を画面に出す |
| 手札の表示 | 選択式(「重ねて表…」と表示が途中で切れていた。手札の並べ方の選択と思われる) |
| 超GR / 超次元 | 切替(OFF)。専用ゾーンの表示と思われる(推測) |
| デッキスリーブ / プレイマット | 有料(支援プラン) |
| オフライン保存 | 「0/2デッキ・合計0KB」。オフライン用に保存でき、上限あり |

### 2.4 操作(観察と推測)

- **ドラッグ&ドロップ**でカードをゾーン間で動かす(観察: ドラッグの案内文「To pick up a draggable item, press the space bar…」が出ている。これは dnd-kit というライブラリの標準の文言なので、そのライブラリを使っていると推測)。キーボード操作(スペースで持ち上げ、矢印で移動)にも対応していると思われる。
- ゾーンのボタン(一覧、全アンタップ)は**小さなボタンで常に出す**方式。
- 元に戻す/やり直す(矢印のアイコンから判断)、非公開領域(伏せ札)の表示切替(目のアイコン。画面内に「非公開領域」の文言あり)が、ツールバーに常設。

### 2.5 DM_SIM への取り入れ方

| 参考点 | DM_SIM での扱い |
|---|---|
| 6ゾーン+右側に山札・墓地を縦に置く配置 | 採用候補。**対戦では相手側の盤面を上に鏡写し**で置く(design 9章)。狭い幅でも成立する縦積みを基本にしておくと、将来のスマホ対応にもつながる |
| ゾーンごとの「一覧」「全アンタップ」「折りたたみ」 | 採用。マナ・墓地・シールドは枚数が多いので一覧が必要 |
| 操作履歴(ターンごと、自動処理にタグ) | 採用。対戦ログに「自動」「手動」「効果名」を付ける。さらに **因果ツリー**(effects.md 11.4)に発展させる |
| 元に戻す/やり直す | 採用。対戦では「1手戻す(練習用の設定)」、ソリティア調査の**手動プレイでは自由に戻せる**(effects.md 11.5) |
| 非公開領域の表示切替(目のアイコン) | 採用。人間 vs CPU では相手の伏せ札は元々見えないが、**一人回しの練習モード**では自分のシールド・山札の中身を見る切替が役に立つ |
| 効果自動処理のON/OFFと、結果表示のON/OFF | **採用(重要)**。DM_SIM では `autoSingle`(選択肢が1つなら自動)、`ack` を自動で閉じる設定、同時誘発の順序を毎回選ぶか自動か(spec Q17)に当たる。「自動でやったこと」を必ず履歴に残す |
| 複数デッキのタブ | 後回し。デッキの切替はメニューで足りる |
| カード拡大表示のパネル | 採用。画像なしなので**テキスト全文+現在の派生値**(現在のコスト・パワー・付与された能力)を出す |
| 有料機能・広告 | 関係なし |

## 3. データ(観察)

### 3.1 デッキのデータ

```
deck: { id, name, format("original"), isPublic, cardSort, createdAt, updatedAt, ... ,
        cards: [ { card: Card, quantity: number, zone: "main" } ] }
```

### 3.2 カードのデータ

`Card` に入っている項目は次のとおり。DM_SIM のカードJSON(spec 4.1)と**ほぼ同じ粒度**で、足りない項目がないかの点検に使える。

| サイトの項目 | 内容 | DM_SIM |
|---|---|---|
| id / cardNumber | 内部ID(UUID)/ 型番(`dm25ex3-SP3` など) | `id` は公式の型番を使う(spec 4.1) |
| name / nameKana / `keyword[]` | 名前 / よみ / 検索用の読み仮名の表記ゆれ | 検索用。後回し |
| setCode / setName / rarity | 収録弾 / レアリティ | 参考情報(収録弾による文言差の管理に使える) |
| cardType | クリーチャー / 呪文 / S-MAX進化クリーチャー … | `faces[].type` |
| civilizations / cost / power / race | 文明 / コスト / パワー / 種族 | 同じ |
| description | **カードの文章(原文に近いテキスト)** | `text`(要約でなく原文を持つか検討。権利に注意) |
| `twinpactSides[]` | ツインパクトの**両面を別オブジェクトで保持** | `faces[]` と同じ構造 |
| isFoil / isPromo / imageUrl | 見た目・画像の場所 | 画像は当面なし。`image` は任意項目 |
| deckUsageCount | 他ユーザーのデッキでの採用数 | 不要 |

### 3.3 「効果スクリプト」のデータ

カードIDをまとめて渡すと、**カードごとの効果の一覧**が返る(観察: `/api/cards/effect-scripts?ids=…`、バージョン `v=10`)。1つの効果は次の形。

```jsonc
{
  "id": "e1",
  "text": "このクリーチャーが出た時、自分の山札の上から３枚を見る。…",   // 効果の文章
  "label": "山札の上から3枚を見て手札・マナ・墓地に振り分ける",         // 画面に出す短い説明
  "trigger": "出た時",                                              // 誘発タイミング(日本語の自由文字列)
  "steps": [ { "t": "LOOK_DISTRIBUTE", "n": 3, "rest": "graveyard",
               "assign": [ { "n": 1, "to": "hand" }, { "n": 1, "to": "mana" } ] } ]
}
```

**手順(`steps`)の種類**(観察: 手持ちデッキの14種のカードで使われていたもの。全種類ではない)。

| `t` | 内容 | パラメータの例 |
|---|---|---|
| `DRAW` | 引く | `n` |
| `MANA_BOOST` | 山札の上をマナへ | `n` |
| `LOOK_DISTRIBUTE` | 山札の上N枚を見て振り分け | `n`, `assign[{to, n(数 または {upTo}), tapped?}]`, `rest`(残りの行き先), `total` |
| `MOVE_SELECT` | 選んで別ゾーンへ動かす | `from`, `to`, `n`(数 / `{upTo}` / `{allBut:3}` のいずれか), `filter`, `excludeSelf` |
| `SELF_TO_ZONE` | このカード自身を動かす | `to`(graveyard / battle) |
| `PUT_INTO_BATTLE` | 他ゾーンからバトルゾーンに出す | `from`(mana / graveyard)`, n`, `filter{cardType, costMax{var / count+plus}}` |
| `SHIELD_ADD` | 山札の上をシールドに | `n` |
| `YOBINION` | ヨビニオン専用の手順 | なし |
| `OPTIONAL` | 「してもよい」 | `prompt`, `steps` |
| `IF` | 条件分岐 | `condition{kind:count, where, min}`, `then`, `else` |
| `REPEAT` | N回繰り返し | `times`, `steps` |
| `CHOOSE_MODE` | 選択肢から選ぶ | `modes[{label, steps}]`, `prompt` |
| `ASK_NUMBER` | **数値を人間に入力させる**(変数に保存) | `key`, `prompt`, `max` |
| `OPPONENT_ONLY` | 相手に関する処理。**自動処理せず、文章を表示するだけ** | `note` |
| `MANUAL` | 人間に手動で処理させる注意書き | `note` |
| `UNSUPPORTED` | 表現できない(理由つき) | `reason` |

### 3.4 手持ちデッキのカードの自動化の度合い(観察)

| カード | 自動で表現できている | 自動化できていない(注意書き/未対応) |
|---|---|---|
| フェアリー・ライフ | ブースト | |
| フェアリー・Re:ライフ | ブースト | G・ストライク(相手のクリーチャーを選ぶ) |
| ワクムテラス/オリジナル・ライフ | ドロー、ブースト | |
| 天災 デドダム | 上3枚の振り分け | |
| ヨビニオン・マルル | ヨビニオン、2体目の効果(手札かタップしてマナ。残りは山札の下) | |
| ティンパニ=シンバリー | ヨビニオン、自分を破壊(任意) | 相手のクリーチャーを選んで破壊 |
| 逆転の剣スカイソード | マナからの召喚(枚数より小さいコスト) | 相手をマナに置く |
| 終末の監視者 ジ・ウォッチ | 2体まで手札に戻す | 相手のクリーチャーを含む選択。**「ターンの残りをとばす」は項目自体なし** |
| 終末縫合王 キーナリー | シールド追加、墓地からの召喚(選んだコスト以下。コストは人間が入力) | EXライフのシールドの管理(手動)、相手のバウンス、**トリガー抑制** |
| ロスト・Re:ソウル | | 相手の手札を全部捨てさせる、G・ストライク |
| CRYMAX ジャオウガ | 置換の代わり(IFと選択で表現)、自分のシールドを3枚残す | 置換が起きたかどうかの扱い(手動)、相手側の処理、攻撃時の効果 |
| 流星のガイアッシュ・カイザー | ドロー、無料召喚(任意) | コスト軽減、相手の攻撃制限(スクリプトなし) |
| 魔誕の斬将オルゲイト | | 相手のバウンス。**相手のクリーチャーの能力のコピーは `UNSUPPORTED`** |
| 修羅の死神フミシュナ | 呪文面の「2回選ぶ」(`REPEAT`+`CHOOSE_MODE`)、任意のドロー | 相手の手札を捨てさせる、相手のクリーチャーを戻す |

- **キーワード能力(ブロッカー、W/T・ブレイカー、S・トリガー、ハイパーエナジー、ジャストダイバー等)は、スクリプトの項目にない**(観察)。画面では文章を見て人間が扱う設計と思われる(推測)。
- 一人回しなので相手が存在せず、**相手が絡む処理は `OPPONENT_ONLY`、置換・コピーは `MANUAL` / `UNSUPPORTED`** になっている。ここが、DM_SIM の対戦エンジンが追加で解く必要がある部分。

## 4. 効果の記述方法の比較

| 観点 | duel-hub の効果スクリプト | DM_SIM の設計(effects.md) | 取り入れること |
|---|---|---|---|
| 形式 | 効果ごとに `text` / `label` / `trigger` / `steps` | `Ability`(`trigger` / `spell` / `static` / `replace` …)+ `steps` | **能力に `label`(画面用の短い説明)を持たせる**。待機プールの表示(effects.md 11.4)で使う |
| 誘発タイミング | 日本語の自由文字列(`"出た時"`、`"召喚によって出た時"`) | 原始イベント+パターン(`TriggerSpec`) | 変更なし。表記を画面に出す時は、パターンから日本語の文を生成する |
| 手順 | `DRAW` / `MANA_BOOST` / `MOVE_SELECT` / … 専用の命令が多い | 少数の汎用の `act`(`move` / `draw` / `lookTop` / `assign` …) | **便利な糖衣構文は採用**: `MANA_BOOST` は `move(山札の上 → マナ)`、`DRAW` は `draw` に展開して読み込む |
| 振り分け | `LOOK_DISTRIBUTE`(上N枚→手札/マナ/墓地、残り、`tapped`) | `lookTop` + `assign` | `tapped`(タップしてマナ)、`upTo`(0〜N)、`rest`(残りの行き先)を `assign` に足す(マルルの2体目の効果で必要) |
| 数の指定 | `n`、`{upTo}`、`{allBut:3}` | `Qty`(min/max) | `allBut`(「N枚残して全部」。ジャオウガ)を `Qty` に足す |
| 数値の変数 | `ASK_NUMBER`(人間が入力して変数に) | 変数は `select` の結果から取る | **ソリティア調査では、相手が存在しない状況の値**(キーナリーが選んだ相手のコスト)を入力する手段が要る。`ask(number)` を足し、調査では「**相手のクリーチャーがいない = 選ばない**」として扱う(spec Q14) |
| 相手の処理 | `OPPONENT_ONLY`(注意書き) | `select(who: opponent)`、相手プレイヤーの pending | **対戦エンジンで実装する**(これが一人回しツールとの違い) |
| 置換・コピー | `MANUAL` / `UNSUPPORTED` | `replace` パイプライン、`copyAbility` | **差別化点**。ここが DM_SIM の価値 |
| 手動の逃げ道 | `MANUAL`(人間に注意書きを出す) | なし(未対応能力は起動時エラー) | **ソリティア調査・一人回しモードでは、未対応の能力を「手動で処理」に落とす逃げ道**を用意するか検討(第5章) |

## 5. 設計へのフィードバック(候補)

DM_SIM の設計文書への反映案。今は参考として記録し、採用は実装時に決める。

1. **`label` を能力に追加する**(待機プール・ログ・確認ダイアログに出す短い説明)。`text`(原文の要約)と分ける。
2. **`assign` に `tapped` / `upTo` / `rest` を足す**(デドダム、マルル、ドンドン火噴くナウで必要)。`Qty` に `allBut` を足す(ジャオウガ)。
3. **一人回しモード(手動寄り)を作るか**: 本ツールのように、自動処理を切って**人間がカードを自由に動かして**回すモード。DM_SIM の確率調査で「自動」と「人間が確かめる」を併用するのに役立つ。エンジンのゾーン移動の原始操作(`move`)をそのまま手動操作にも使えるので、追加の実装は小さい(UIの「自由移動」を足すだけ)。
4. **自動処理した結果の可視化**(「効果の処理結果を表示」)。履歴に「自動」「手動」を区別して残す。
5. **未対応能力の扱い**: 対戦では起動時エラー(現状の方針)。一人回し/ソリティアでは `MANUAL`(「この効果は手動で処理してください」)に落とす選択肢を用意する。
6. **座標系・見た目**: 狭い幅でも成立する縦積みを基本にし、PC幅では横に広げる(将来のスマホ対応)。

## 6. 未確認事項

- 「次のターン」で行われる処理(アンタップ、ドロー、マナチャージの扱い)。
- 「直感(beta)」の内容。
- ドラッグ操作の細部(ドロップ先の判定、複数枚の移動、シールドのブレイク操作)。
- 効果スクリプトの全命令の種類(今回確認したのは手持ちデッキの14種のカードで使われたもの)。
- 利用規約(データの取得・利用に関する条項)。
