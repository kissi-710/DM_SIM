## 2. 用語

| 用語 | 意味 |
|---|---|
| 山札 / 手札 / マナゾーン / シールドゾーン / バトルゾーン / 墓地 | カードが置かれる6つの領域 |
| タップ / アンタップ | カードを横向き(使用済み)/ 縦向き(使用可能)にした状態 |

## 3. ゲームルール仕様(実装対象)

- 準拠: 総合ゲームルール Ver.1.52。条番号は、PDF の全文を取り出して**原文で確認済み**(2026-10-14)。条文ごとの要約・公式 Q&A・コードとの照合は [rules-reference.md](./rules-reference.md)、出典の一覧と使い分けは [rules-sources.md](./rules-sources.md)。**キーワード能力の個別定義は総合ルールになく、公式 Q&A が根拠**になる。
- カードごとの効果は decks.md を参照。

### 3.1 デッキ

- 1デッキ40枚(対象デッキはいずれも40枚)。
- 構築制限(40枚・同名4枚まで)は、**対戦モードでは強制**し、**シミュレータ(ソリティア調査)では「自由モード」**(枚数・同名制限なし)も選べる(Q10 の仮決定)。
- デッキはカードIDの配列で表す。

### 3.2 ゲーム開始

1. 双方の山札をシャッフルする。
2. 先攻・後攻を決める。公式ルールはじゃんけんで決めるが、**このアプリでは「ランダム」か「どちらかを選択」を選べる**。
3. 各プレイヤーの山札の上から5枚を、裏向きでシールドゾーンに置く(113.1 / 406.1)。
4. 各プレイヤーが山札の上から5枚を手札にする(103.3 / 402.1)。
5. マリガン(引き直し)は行わない。現行ルールにマリガンの定めは確認できなかった。

### 3.3 ターンの進行

自分のターンは次の順に進む(501〜511)。

| ステップ | 内容 |
|---|---|
| ① ターン開始 | 自分のマナゾーンとバトルゾーンのカードをすべてアンタップする(ターン起因処理) |
| ② ドロー | 山札の上から1枚を手札に加える。**先攻の1ターン目はドローしない**(103.5) |
| ③ マナチャージ | 手札から1枚を選び、マナゾーンに置く(任意・1ターンに1枚まで)。多色カードはタップ状態で置く(405.1) |
| ④ メイン | コストを払い、手札のクリーチャーを召喚する/呪文を唱える。条件を満たす限り何枚でも可 |
| ⑤ 攻撃 | 攻撃クリーチャー指定 → ブロッククリーチャー指定 → バトル(またはシールドブレイク / ダイレクトアタック) → 攻撃終了、を繰り返す |
| ⑥ ターン終了 | ターン終了時の効果を処理し、手番を相手に渡す |

### 3.4 コストの支払い

- コストを支払うには、マナゾーンのアンタップ状態のカードをタップする。
- **コストに含まれる文明ごとに、その文明を持つマナ1枚をタップし、残りはマナの数値の合計で満たす**(112.2a)。例: 2文明のコスト7なら、各文明のマナを1枚ずつ含めて計7枚タップする。
- **マナゾーンの多色カード1枚は、複数の文明を同時に満たせない**(どれか1つの文明として数える)(112.2a)。
- コスト軽減で、コストが文明の数より小さくなった場合は、文明の支払いを優先し、余ったマナは消える(112.2b)。
- 支払いは、どのマナをタップするかの割り当て問題になる。初期は自動で割り当てる(手札の他のカードの文明条件を残すものを優先)(仮)。

#### 3.4.1 マナと文明の方針(確定。調査と実装の対応)

公式の総合ルール(決定時に参照した版は Ver.1.47。基準版は現在 Ver.1.52)・公式Q&A・DMwiki(マナ / 多色 / コスト軽減)を突き合わせて決めた。コードとテストはこの表に従う。

| # | 方針 | 実装 / テスト |
|---|---|---|
| M-1 | **多色カードは、マナゾーンに置かれる時にタップ状態で置く。** 文明が2つでも3つ以上でも同じ。置かれる前のゾーンで多色だったカードも同じ(マナチャージ・ブースト・バトルゾーンから置く・進化元の下のカードも)。ツインパクトは両面の文明の和集合で多色として扱う | `ops.ts` doMove(`to === 'mana'`)。`tests/rules/mana-civ.test.ts` |
| M-2 | **マナ1枚は、タップした時に1つの文明(と1点)のマナを生む。** 多色のマナは、持つ文明のうち1つだけを選んで使う。同じコストの支払いで、1枚が2つの文明を満たすことはない | `derive.ts` planPayment / `procs.ts` covers |
| M-3 | **カードの文明ごとに、その文明を持つ別々のマナを最低1枚タップする。** 残りのコスト(数値)は、どの文明のマナでもよい。タップする枚数は `max(コスト, 文明の数)` | `derive.ts` payNeed |
| M-4 | **2文明のカードは、コストがいくつでも最低2枚、3文明は最低3枚タップする。** コスト軽減で下がっても、文明の数を下回らない(Q&A: スター・ピッピー、アカシック・ファイナル)。**単色のカードも、軽減してコストが0になった場合でも、その文明のマナを1枚は払う**(「コストを支払わずに」使う場合だけ支払わない) | `derive.ts` payNeed |
| M-5 | 例: 水闇自然のデドダム(コスト3)は、マナゾーンが「水闇自然・水・水」では召喚できない(多色マナが闇と自然を同時に満たせず、水だけが2枚余る)。「水闇自然・水・闇」「水・闇・自然」なら召喚できる | `tests/rules/mana-civ.test.ts` |
| M-6 | 手動で払う場合も同じ検証を通す(枚数が `max(コスト, 文明の数)` に一致し、文明ごとに別のマナで満たせること)。自動払いは、手札の他のカードの文明を残すマナを優先して残す | `procs.ts` planPlay |

**v1 の範囲外(カードプールに無いため):** 無色カード(文明を持たない。マナは点数だけを生む)、マナ数0の5色レインボー(点数0で、文明の支払いにだけ使える)、O・ドライブのようなタップ枚数の数え方。`registry` は文明のないカードを不正として弾くので、実装も無色を想定していない。

### 3.5 召喚と呪文

- クリーチャーを召喚すると、バトルゾーンに出る。
- 呪文を唱えると、効果を処理して墓地に置く(カードの指示で、墓地に置かない場合もある)。
- ツインパクトは、使う面(クリーチャー面 / 呪文面)のコスト・文明・種類で扱う。
- S・トリガー、効果などで「コストを支払わずに」使う場合は、コストの支払いを行わない。

### 3.6 攻撃とバトル

- **攻撃できるのは、自分のターン開始時から継続してバトルゾーンにいるクリーチャー**(301.4 / 301.5)。攻撃するとタップする。出たターンに攻撃できる能力は、スピードアタッカーとマッハファイターなど(下記)。
- 攻撃対象は、**相手プレイヤー**か、**相手のタップ状態のクリーチャー**(アンタップ状態のクリーチャーは、能力がなければ攻撃できない)。
- **スピードアタッカー**: 出たターンから攻撃できる(アンタップ状態のクリーチャーは攻撃できない)。
- **マッハファイター**: 出たターンに、相手のクリーチャーを(タップ・アンタップを問わず)攻撃できる。**プレイヤーは攻撃できない**。
- **ブロッカー**: 相手のクリーチャーが攻撃する時(攻撃クリーチャー指定の後、ブロッククリーチャー指定のステップ)、アンタップ状態のブロッカー1体をタップして、攻撃対象をそのブロッカーに変更してもよい。
- **バトル**: パワーが高い方が勝ち、低い方は破壊されて墓地へ。**同じパワーなら両方破壊**(115.3b)。

### 3.7 シールドブレイクと勝利

- プレイヤーが攻撃され、相手のシールドが残っている場合、**ブレイカー数**(通常1、W・ブレイカーは2、T・ブレイカーは3)の枚数だけ、攻撃された側のシールドが手札に加わる。どのシールドを割るかは攻撃側が選ぶ(裏向きなので、実質ランダムで扱ってよい: 仮)。
- シールド枚数がブレイカー数より少ない場合は、残りをすべて割る。
- **攻撃先が変更されないまま、相手のシールドが0枚の状態でプレイヤーへの攻撃が成立したら、攻撃側の勝利**(ダイレクトアタック)(104.2a)。シールドを割り切った攻撃そのものでは勝てない(次の攻撃が必要)。
- **山札が0枚になったプレイヤーは敗北する**(104.2b)。山札が0枚の時にドローしても、何も起こらない(114.6)。※勝敗の判定タイミングは、公式では効果の処理の途中で一瞬でも0枚になれば0枚とみなす(104.2b。rules-reference.md 11章 L9)。実装がそれに合っているかは未確認(同 12章 D-6、ISSUES.md ISSUE-08)。
- 引き分けの規定は確認できなかった。シミュレーション用にだけ、**ターン上限(暫定100)で引き分け扱い**にして記録する。

### 3.8 S・トリガーとG・ストライク

1. ブレイクされたシールドが手札に加わる時、持ち主は、S・トリガーなどの能力を持つカードを**宣言**できる(113.6)。
2. 宣言がすべて終わってから、カードが手札に移り、宣言されたものを**1枚ずつ解決**する(112.3a)。解決中に新たにブレイクされて宣言されたS・トリガーは、すでに待機しているものより先に解決する(101.4g)。
3. 使わない場合は、通常通り手札に加える。
4. G・ストライクは、シールドゾーンから手札に加える時に相手に見せて使う能力で、同じ「宣言」の枠組みで扱う(カードの効果は decks.md)。

### 3.9 v1で扱う能力

対象デッキのカードが持つ能力すべて。一覧と、必要なエンジンの仕組みは **decks.md の4章**を参照。主なもの:

- キーワード: ブロッカー、W/T・ブレイカー、スピードアタッカー、マッハファイター、S・トリガー、G・ストライク、EXライフ、ジャストダイバー、ハイパーエナジー、シンパシー、ヨビニオン、侵略、進化・S-MAX進化、革命0/2、マナからの召喚
- 効果: ブースト、ドロー、ハンデス(見ずに選ぶ)、破壊、バウンス、墓地からの召喚・詠唱、パワー修正、ターンの残りをとばす、能力のコピー、置換効果、継続効果(コスト軽減・攻撃制限・呪文制限)

### 3.10 同時に起きる処理の順序

- 能力が同時に誘発した場合、**S・トリガーを最優先**(ターンプレイヤー → 非ターンプレイヤー)し、そのあと**ターンプレイヤーの能力から先に**解決する(101.4 / 101.4a)。**同じプレイヤーの能力同士は、そのプレイヤーが好きな順で解決できる**。プレイヤー間の先後(ターンプレイヤー優先)は選べない。
- 処理の途中で新しく誘発した能力は待機し、処理中のものを先に終える(101.4a / 101.4c)。処理中に新しく待機したS・トリガーは、すでに待機していたものより先に解決する(101.4g)。バトルによる誘発もターンプレイヤー側から(115.2 / 115.3d)。
- 置換効果以外の効果は、処理中に割り込ませられない(101.4d)。
- 実装方式は [effects.md 第5章](./effects.md#5-トリガーの処理待機プールとチェックポイント)。

### 3.11 置換効果

- 同じ出来事に適用できる置換効果は**1つだけ**。一度置換された出来事は、さらに置換されない(101.5)。→ 置換は連鎖しない(キーナリー・ジャオウガ・ヨビニオン・トライブの身代わり/置換の処理で重要)。
- 複数の置換効果がある場合は、ターンプレイヤーのものを優先する。同じプレイヤーの複数の置換効果からは、そのプレイヤーが選ぶ(101.5b)。
- 複数枚を引く場合は、1枚ずつ置換を済ませてから次を引く(114.4a)。

### 3.12 選択肢を持つ能力(「N回選ぶ」呪文など)

- 選択肢は、**能力の解決時に選ぶ**(トリガー時や呪文を唱えた時点ではない)(2022年6月のルール変更)。
- 1つの能力で複数回選ぶ場合は、**解決の開始時に必要な回数分をまとめて選び**、途中の結果を見てから選び直すことはできない。選んだものは、**能力の文章の上に書かれたものから順に**解決する。
- 「全部使える」条件がある呪文(5色の決断、ブレイン・スラッシュ)の宣言の扱いは、公式の記述が見つからなかった。このアプリでは、UI上で**選択を必ず明示させる**(暗黙に全部選ばない)(仮)。

### 3.13 カード効果・タイミング・操作の要件

人間が画面で遊べること、AIとシミュレータが同じ経路で動くことを前提に、次を満たす。詳細は [effects.md](./effects.md)。

1. **汎用性**: 新しいカードを足すとき、原則としてカードのデータ(能力の記述)だけを書く。エンジンのコードを触るのは「原始操作が足りない時」だけ。
2. **タイミング**: 次の「〜時」を表現できる。出た時、召喚によって出た時、重なった時(進化・侵略)、攻撃する時、ブロックされた時、バトルに勝った/負けた時、破壊された時、バトルゾーンを離れた時、手札に加わった時、捨てた時、マナゾーンに置かれた時、呪文を唱えた時、シールドがブレイクされた時、ターン開始/終了時、相手のターン終了時、能力がトリガーした時、ゲームに負ける時。
3. **条件**: 「各ターンN体目」「1ターンに1回」「そのターンに〜した場合」「自分のターン/相手のターンのみ」を扱える。
4. **同時誘発**: 3.10 の順序で解決する。同じプレイヤーの複数の能力は、人間は毎回選べる(設定で自動にもできる)。AIは自分で選ぶ。
5. **置換**: 3.11。複数あれば選べる。「してもよい」の置換は任意。
6. **継続効果**: コスト軽減、パワー修正、攻撃/呪文の制限、能力の付与、「選ばれない」を扱える。期限は「そのターン中」「次の自分のターンのはじめまで」「発生源がいる間」。
7. **選択**: 対象選択(相手が選ぶものを含む)、複数選択、割り振り(山札の上N枚)、選択肢(N回、同じ選択可)、任意の確認、順序の選択を、同じ画面部品(入力形式7種)で行える。
8. **操作**: 手札からマナ/バトルゾーンへのドラッグ、クリーチャーから対象へのドラッグ(攻撃)、すべてにクリックでの代替操作。ドロップ可能な場所を強調する。
9. **可視化**: 誘発して待機中の能力の一覧、解決中の能力、因果ツリー形式のログを表示する。
10. **再現性**: 同じシードと行動列で、同じイベント列になる。バグ報告用に保存・再生できる。

### 4.2 能力(`abilities`)の種類

| kind | パラメータ | 意味 |
|---|---|---|
| キーワード系 | `blocker` / `breaker(count)` / `shieldTrigger` / `gStrike` / `speedAttacker` / `machFighter` / `exLife` / `justDiver` / `sympathy` / `hyperEnergy` / `yobinion` など | engineが直接解釈する |
| `trigger` | `spec`(イベントパターン・監視ゾーン・条件・回数制限), `optional?`, `steps[]` | 誘発型能力・S・トリガーの本体。「〜時」はイベントパターンで表す(effects.md 4章) |
| `spell` | `steps[]` | 呪文の効果 |
| `static` | `scope`, `mod`, `while?` | 常在型(コスト軽減、パワー修正、攻撃制限、呪文制限、能力付与など) |
| `replace` | `match`, `apply`, `optional?` | 置換効果(破壊→マナ、離れる→身代わり、「出た時」不発など) |
| `permission` | `play`, `from`, `after?` | マナから召喚、墓地から唱える(唱えた後は山札の下) |
| `costMod` | `mod` | シンパシー、ハイパーエナジー、軽減 |
| `custom` | `handler` | 最後の手段(原始操作だけを呼ぶ個別コード)。 effects.md 6.6 |

「N回選ぶ」(`modes`)、ヨビニオン、EXライフなどは、キーワード名から展開するテンプレートで書く。

効果の記述(`steps`)は **原始操作(`act`)・選択(`select`)・任意(`may`)・分岐(`if`)・繰り返し(`each` / `repeat`)・選択肢(`modes`)** の組み合わせ。原始操作の一覧は effects.md 6.3(`move` / `draw` / `lookTop` / `assign` / `tap` / `addShield` / `addEffect` / `summonFree` / `castFree` / `skipRestOfTurn` / `copyAbility` など。必要になったものから追加)。

### 4.3 検証

- 起動時にすべてのJSONを検証する。必須項目の不足、未知の `kind`、未対応の能力があればエラーで停止する。
- デッキに含まれるカードIDが存在し、全カードの能力が実装済みであることを確認する。

## 5. 機能仕様: 対戦

### 5.1 モードと設定

- **人間 vs CPU**、**CPU vs CPU** の2モード。座席ごとに「人間 / CPU(強さ・情報条件)」を選ぶ。
- デッキは、decks.md の2デッキから選ぶ(同じデッキ同士も可)。
- **先攻・後攻**: 「ランダム」/「先攻を選ぶ(自分 or 相手、または座席0・座席1)」から選ぶ。
- シードの指定(任意。指定しなければ自動生成し、結果画面に表示)。
- CPU vs CPU は、**観戦モード**(1試合を再生。速度調整・一時停止・1手進める)と、**バッチ**(7章)の2通り。

### 5.2 対戦画面(人間が操作する場合)

- 表示: 自分の手札・マナ・バトルゾーン・墓地、相手のバトルゾーン・マナ・墓地、双方のシールド枚数・山札枚数・手札枚数(相手の手札の中身は見せない)。現在のターン・ステップ。
- 操作: マナチャージ / 召喚・呪文 / 攻撃(クリーチャー → 対象) / ターン終了。ブロック・S・トリガー・効果の対象選択・選択肢の選択など、選択が必要な時は専用のUIを出す。
- 操作できるものだけ有効にし、選べる対象は強調する(合法手のみ)。
- 対戦ログ(時系列のテキスト)。CPUの手番中は「考え中」を表示し、入力を無効にする。
- 勝敗が決まったら結果と「もう一度」ボタンを表示する。
- 取り消し(undo): v1では含めない(状態をコピーできるので、後から追加できる)。

### 5.3 CPU

- 強さ: ランダム / ルールベース / モンテカルロ探索(実装済みのものだけ選べる)。
- **情報条件(相手の隠し情報をどこまで見せるか)** を設定で変えられる。既定は「公平」(人間と同じ)。

| プリセット | 内容 |
|---|---|
| 公平(既定) | 自分から見える情報だけ。相手の手札・シールドの中身、山札の順序は見えない |
| 部分開示 | 相手の手札のうち一部を開示する、手札の「種類」(S・トリガー・ブロッカーの有無など)だけ開示する、など。開示の範囲を設定する |
| 決め打ち | 「相手はこのカードを持っているはず」という仮説を置いて行動する(人間が次のターンに来るカードを見越して動くのに近い)。仮説は設定、またはCPUが推定する |
| 全開示 | 相手の手札・シールドが全部見える(強さの上限を測るため) |

- 相手のデッキリストを既知にするかも設定できる(スターターデッキ同士の対戦では、既知にすることが多い想定)。
- 調整の流れ: まず「公平」で強さを測り(バッチ対戦)、弱ければ「部分開示」「決め打ち」を足して勝率の変化を見る。
- 探索AIの思考時間は上限を設ける(目標は実装後に計測して決める)。

## 6. 機能仕様: シミュレータ(確率調査・パターン調査)

### 6.1 概要

2つの調査ができる。例: 「4ターン目にコスト7のカードを使う」という**目標**に対して、

- **確率調査**: 目標を達成できる**確率**を求める(例: 4ターン目に7コストが打てる確率)。
- **パターン調査**: 目標を達成するための**使用履歴**(どのターンに何をマナチャージし、何を使ったか)にどんなものがあるかを調べる。

どちらも、**ソリティア(相手が何もしない1人回し)**で、**カード効果を含めて**ゲームを進める(ブースト、デドダムの割り振り、ヨビニオンなどの効果も処理する)。目標の条件は、**GUIで組み立てる**(一般化)。

### 6.2 共通の入力

- デッキ(40枚。対象は decks.md の2デッキ)
- 先攻 / 後攻(先攻の1ターン目はドローしない)
- 調べるターン数の上限
- **目標**(6.3)
- 試行回数(山札のシャッフル数)と乱数のシード
- 初期条件(任意): 初手に必ず含めるカード / 含めないカード、山札の上の固定(「初手に◯◯がある場合」を調べたい時)
- プレイ方針(6.4)

### 6.3 目標の指定(GUIの条件ビルダー)

条件は、次の部品を組み合わせて作る(AND / OR / NOT)。内部では、**状態を受け取って真偽を返す条件式**として保存・再利用できる(JSON)。

| 部品 | 例 |
|---|---|
| タイミング | 「Nターン目のメインステップのどこかで」/「Nターン目の終了時に」/「Nターン目までに」 |
| 使える | 条件に合うカードが手札にあり、その時点のマナで支払える |
| 使った | 条件に合うカードを実際に使った(召喚 / 唱えた) |
| カードの条件 | カード名 / コスト(=N、≧N)/ 文明 / 種類(クリーチャー・呪文)/ ツインパクトの面 |
| 盤面・ゾーンの条件 | マナの枚数(文明条件つき可)/ 手札に X が K 枚以上 / バトルゾーンに X がいる / 墓地に X がある / シールドの枚数 |

初期のプリセット例:
- 「4ターン目に、コスト7のカードを使う」(パターン調査・確率調査の両方で使う基本例)
- 「3ターン目までにマナが5枚以上になる」
- 「初手に特定のカードがある」

「使える」と「使った」の区別、「コスト7」を実コストで数えるか表記コストで数えるかなどの細部は、Q11 の仮決定(9.2)に従う。

### 6.4 確率調査

- 出力: **達成率(%)**、試行回数、95%信頼区間。「Nターン目までに達成する確率」の累積グラフと、達成ターンの分布。
- 達成率は、**2通りを並べて出す**(仮、Q12):
  - **方針プレイ**: プレイ方針(自動プレイAI)で進めた場合の達成率。現実的な打ち方での確率。
  - **探索による上限**: 各シャッフルについて、行動を探索し、**目標に到達できる打ち方が1つでもあれば達成**とみなす。山札の並びを事前に知っている前提なので、現実の確率より高くなる(上限値)。
- 簡単な条件(カードを引く確率など)は、**超幾何分布の厳密値**も併記して、シミュレーションの検算に使う。

### 6.5 パターン調査

- 目標を達成する**使用履歴**を、行動の探索で集める。履歴は、ターンごとの「マナチャージしたカード」「使ったカード(順序つき)」「効果の選択(デドダムの割り振りなど)」を並べたもの。
- 履歴を**パターン**にまとめる(同一視のルールは設定できる。既定は「ターンごとのマナチャージ+使用カード(順序あり)」。「使用カードの集合だけ」に粗くすることもできる)(仮、Q13)。
- 出力:
  - パターン一覧(出現が多い順): ターンごとの履歴、出現割合(全試行に対して / 達成した試行に対して)
  - 各パターンの必要条件の要約(例: 「初手に A がある試行が◯%」)と、代表的なシャッフルの例
  - 絞り込み: 特定のカードを含む / 含まない、初手の条件
  - **履歴の再生**: パターンを1つ選ぶと、盤面の推移をターンごとに再生する(対戦画面の表示を再利用)

### 6.6 画面

条件ビルダー → 実行(進捗表示・キャンセル。重い処理はWorkerで実行)→ 結果(確率・グラフ・パターン表)→ 保存 / エクスポート(JSON・CSV)。

### 6.7 エンジンへの要求(設計に反映)

- 相手の手番を省略できるソリティアモード。
- 行動の探索ができるよう、状態を丸ごとコピーでき、同じ状態から決定的に進められること。
- 効果の選択(デドダムの割り振り、ヨビニオンを使うか、など)も、探索の対象になる「行動」として表せること。

## 7. 機能仕様: AI同士のバッチ対戦(CLI)

### 7.1 入力

デッキA・デッキB、AI種別と情報条件(各側)、試合数、シード、先攻の扱い(固定 / 交互 / ランダム)。

### 7.2 出力

- 勝敗数・勝率(95%信頼区間つき)・引き分け数・平均ターン数。
- 先攻 / 後攻別の勝率。
- 情報条件を変えた比較(公平 / 部分開示 / 全開示)。CPUの強さ調整に使う。
- (後続)カード別の分析。「カード単体の強さ」は、デッキから1枚入れ替えた時の勝率差で測るのを基本とする(仮)。

### 7.3 実行

- `npm run batch -- --deckA ... --deckB ... --games 5000 --seed 1` の形(仮)。同じ引数・同じコードなら同じ結果になる(再現性)。

## 8. 非機能要件

| 項目 | 内容 |
|---|---|
| 再現性 | すべての乱数はシード指定可能。同じシード・同じ操作列で同じ結果 |
| 性能(暫定目標) | ランダム同士の1試合が数ms以内。確率・パターン調査は、数千〜1万シャッフルで数十秒〜数分(探索の重さで変わる) |
| UI応答性 | 探索・シミュレーションはWorkerで実行し、UIスレッドを塞がない |
| 品質 | engineはVitestで単体テスト。ランダム同士の数千試合スモークテストが常に通る |
| 対応環境 | 最新のPC向けブラウザ(Chrome / Edge など)。**将来スマホに対応できる作り**にする(レイアウトとロジックを分け、ホバー前提の操作を避ける) |
| 言語 | UI・ログは日本語 |
| 開発環境 | Windows、Node.js(現行LTS。Q9 の仮決定、9.2) |
