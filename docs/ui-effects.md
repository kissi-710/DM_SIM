# 対戦画面の演出(ターン遷移・攻撃・破壊・シールドブレイクなど)

シミュレータとしての正確さに加え、カードゲームとして「いま何が起きたか」が見て分かるよう、見せ場に演出を足す。
**演出は見た目だけの層**で、ゲームの進行と CPU の手の選択には関与しない。設計の約束(§1)を最初に置く。

## 0. 方針の要約(最初に読む)

### 0.1 目的
このシミュレータは「ルールが正しい」ことが第一で、その上で**カードゲームとして遊べる見た目**にする。ターンが一瞬で切り替わる・何が破壊されたか分からない・攻撃の狙いが見えない、といった「速すぎて追えない」問題を、演出で解く。ゲームの結果・CPU の強さ・再現性は、演出によって一切変えない。

### 0.2 方針(9つ)
| # | 方針 | 理由 |
|---|---|---|
| 1 | **演出は見た目だけの層。** engine のイベント(`Ev`)から作る純粋関数が判定し、状態は読むだけ | design.md §9「論理状態と表示状態を分ける」。engine・AI・棋譜に触れないので、ルールの検証(テスト・Rust 差分)を壊さない |
| 2 | **CPU の手は演出に依存しない。影響するのは待ち時間だけ。** 探索への入力は「状態 + 手数で決まるシード」のみ | 演出の有無・速さで対戦結果が変わると、バッチ・再現・AI の質の測定が崩れる。同じシードなら、通常・高速・オフで行動列が一致する(テストで固定) |
| 3 | **通常 / 高速 / オフ の3段階。オフは従来の表示そのもの。** 高速は長さを半分にする(約 2 倍) | 慣れた人・観戦・大量の対戦では演出が邪魔になる。オフでオーバーレイ・アニメーション・待ち時間のすべてが止まる設計を最初から要件にした |
| 4 | **隠れた情報を出さない。** 名前を出すのは公開された場面のカードだけ。シールド・山札は枚数のみ | 演出が情報漏れの経路にならないように(シールドブレイクは「×N」だけ) |
| 5 | **操作を妨げない。** オーバーレイは `pointer-events: none`・`aria-hidden`。軽い演出は待たせない | 演出中も人間は操作できる。演出のせいで操作が遅れない |
| 6 | **「何が起きたか」を分かるようにするものを優先し、飾りは控える。** 破壊は元の位置から行き先へ飛ばす、攻撃は対象へ線を引く、触れない状態は常時表示する | 目的は見栄えより理解。情報になるもの(手番の縁取り・触れない状態)は、演出をオフにしても残す |
| 7 | **処理の重さ(待たせるか)も見せ場ごとに変える。** 重い(バナー・攻撃線・ゴースト。CPU の待ちに入れる)/ 軽い(ドロー・ステップ・離れたカードのチップ。待たせない)/ 盤面の動き(CSS) | 全部を重くするとテンポが死ぬ。自分の召喚・呪文・攻撃宣言は本人が分かっているので出さず、切り札(革命チェンジ・侵略)と、ターン遷移・ブロック・ブレイク・トリガーは自分の分も出す |
| 8 ★ | **演出の重みは「試合結果への影響の大きさ」に比例させる。** S・トリガー / G・ストライク(逆転の一手)・革命チェンジ・侵略(切り札)・ラスト・シールド・ダイレクトアタックは**決定的**として最も豪華に、ターン・呪文・攻撃・ブロック・シールドブレイクは**重要**、召喚は**軽く**する(§2.4) | デュエマでは、一手が試合をひっくり返す。プレイヤーが「いま何が起きたか」を最も知りたいのは勝敗に直結する場面で、そこが軽いと見落とす。逆に、頻繁に起きて結果に影響しにくいもの(召喚・ドロー)を派手にすると、決定的な場面が埋もれる。**重みは、新しい演出を足す時の判断基準でもある** |
| 9 | **文言は短く、ゲームの表示らしくする。** 説明調(「〜できます」「〜してください」「〜しています」)・念押し・二重の言い換えを避け、体言止めか短い言い切りにする。意味が伝わるなら一言を足さない(「逆転の一手」「王手」のような煽りの一言は置かない)。詳しい説明はツールチップ・カード詳細・文書に回す | くどい文言は、読む手間が増えるだけでなく、機械的な印象を与える。画面上のテキストは、名詞・短い動詞で足りる。札の上の表示は特に短く(🛡 だけ、など)し、正確な言い方はツールチップ・詳細欄に置く |

**重みの使い方**: 重み(`FxTier`)は、演出の長さ・派手さ・扱いを決める。決定的は、画面を暗くし、盤面を揺らし、見せ札(公開されたカードの名前・コスト・テキスト)を出す。1手の演出の数・合計の上限を超えても必ず出す。重要は、帯・線・着弾。軽いは、小さく出す。

### 0.3 構成
```
engine の Ev ──→ fx.ts(純粋関数。cuesOf / drawCuesOf / removalsOf / attackFxOf / ... と、長さ・設定・CPU の待ち)
                    │
   ┌────────────────┼──────────────────────────────┐
 FxLayer        FxTicker / FxGhosts / FxAttack     CSS(.game.fx と --fx-scale)
 (中央のバナー)  (軽いチップ / 離れたカード / 攻撃線・着弾)   (盤面の動き・触れない状態)
                    ▲
              fxRects.ts(描画のたびに各要素の位置を測り、「直前の位置」を渡す。消えた札の元の位置が分かる)
```
- 判定(`fx.ts`)・位置の記憶(`fxRects.ts`)・描画(`Fx*.tsx`)・見た目(CSS)を分けてあり、判定は DOM なしでテストできる。
- 長さは `fxScale(mode)` の倍率で一括して変わる(JS は作る時に、CSS は `--fx-scale` で)。
- 設定は `localStorage` の `dmsim.fx` に保存し、対戦の設定・棋譜・自動保存には含めない(再現性のため)。

### 0.5 確認の方法と、確認できていないこと
- **確認したこと**: 判定の純粋関数、実際のエンジンのイベント(`Sim`)での革命チェンジ・侵略・ジャストダイバー、各コンポーネントの無効化・高速・同じ手で一度だけ、CPU の手が通常・高速・オフで一致すること、型・lint・全テスト・ビルド。実画面では、ターン遷移・ドロー・ステップ・捨てるのゴースト・攻撃線の照準・ダイレクトアタックのバナー・触れない札・革命チェンジ/侵略の帯の見た目を確認した。
- **確認できていないこと**: 破片・火花・入れ替わりの落下などの**動いている最中の見た目**(自動テストは jsdom で、アニメーションの見た目は見られない。画面確認も、非表示のブラウザではアニメーションが進まないため静止画が中心)。実戦での破壊のゴースト・革命チェンジ・侵略・ジャストダイバーの通し確認。
- **既知の限界**: ① 位置は「直前の描画」の測定に頼るので、手の間に大きなスクロール・レイアウト変更があるとずれる(出ないだけで、ゲームには影響しない)。② 進化の下のカードにはゴーストが出ない(チップの名前だけ)。③ 高速は全体を一律に半分にするだけで、演出ごとの調整はない。④ 音・カード画像・S・トリガーの公開の演出・山札切れなどは対象外。
- **新しい演出を足す手順**: ① `fx.ts` に、`Ev` から作る純粋関数と長さを足す(隠れた情報を含めない)。② 重い演出なら `fxHoldMs` に長さを入れる(軽いなら入れない)。③ 描画コンポーネントか CSS を足す(`enabled` が偽なら何も描かない・`--fx-scale` か `scale` を使う)。④ 実イベントでの判定のテスト、無効・高速のテスト、CPU の手が変わらないテストを足す。⑤ この文書の §2 と一覧を更新する。

## 1. 設計の約束

1. **演出は engine のイベント(`Ev`)から作る。** `cuesOf(state, events, me)` は純粋関数で、状態を読むだけ。engine・AI・Worker・棋譜(`GameRecord`)には触れない。
2. **CPU の手の決定は演出に依存しない。** `chooseWithWorker` への入力は「状態 + シード」だけで、シードは `cpuSeed(hashSeed(setup.seed), 経過した手数)`。時間・演出・画面の状態は入らない。演出が CPU に与える影響は、**次の手を打つまでの待ち時間だけ**(`cpuWaitMs`)。同じシードなら、演出の有無で行動列が一致する(テストで固定)。
3. **演出は 通常 / 高速 / オフ の3段階。オフですべて無効になる(従来の表示)。** オフにすると、次の3つが全部止まる。
   - オーバーレイ・チップ・ゴースト(`FxLayer` / `FxTicker` / `FxGhosts` は何も描かず、タイマーも持たない)
   - CSS アニメーション(盤面のルートの `.fx` クラスが付かない。動いたカードの強調は、静止した枠だけになる)
   - 演出のための CPU の待ち時間(オフでは従来と同じ間隔)
4. **隠れた情報を出さない。** シールドブレイクは枚数だけ(カード名なし)。名前を出すのは、公開された場面(召喚・呪文・攻撃宣言・トリガー宣言・場やマナから離れたカード・捨てた手札)のカードだけ。シールド・山札の移動は扱わない。
5. **操作を妨げない。** オーバーレイは `pointer-events: none`・`aria-hidden`。演出中も、人間は盤面を操作できる。

### 2.0 攻撃(攻撃線・ブロック線・着弾)

アタックはデュエマの華なので、**何を攻撃しているか**を線で明示し、割れる・ぶつかる瞬間を派手に見せる(`FxAttack`)。人間が自分で行う攻撃にも出す(バナーは出さないが、線は狙いの確認になる)。

| 場面 | きっかけ | 表示 |
|---|---|---|
| 攻撃線 | `attackDeclared` | 攻撃したクリーチャーから、**赤い線**が対象へ伸びる。対象に照準(二重の輪と十字)を出し、「**シールドへ攻撃**」(相手のシールドの札へ)または「**クリーチャーへ攻撃**」(そのクリーチャーへ)の札を添える。シールドの照準は大きい |
| ブロック線 | `blocked` | ブロッカーから攻撃したクリーチャーへ、**緑の線**と「ブロック!」の札。ブロッカーは緑に光る(§2.1) |
| シールドが砕ける | `shieldBroken` | シールドの札の位置で、閃光・広がる輪・青白い破片が飛び散る。同じ手で続けて割れた分は1つにまとめ、「×N」を出す(W・ブレイカーなど)。盤面のシールドの札は揺れる |
| バトルの火花 | `battleEnded` | 相手(ブロックされたらブロッカー)の位置で、橙の火花。相打ちは「相打ち」を添える。破壊された側は、§2.1 のゴーストで墓地へ向かう |
| ダイレクトアタック | `gameOver`(理由=ダイレクトアタック) | 負けた側のシールドの位置で、赤い大きな着弾と、画面中央の「ダイレクトアタック!」のバナー。**勝敗のパネルは、この演出が終わってから出す**(演出が無効ならすぐ) |

- **時間の並べ方**: 攻撃線(0)→ 着弾(0.45 秒後)。ブロックされたら、攻撃線(0)→ ブロック線(0.45 秒後)→ 着弾(さらに 0.40 秒後)。ブロッカーの選択で手が分かれた時は、その手の中のものだけで組む(線はすぐ始まる)。線は 0.8 秒、着弾は 0.75 秒(高速は半分)。
- **位置**: 攻撃元は `uid:`、クリーチャーは `pid:`(盤面の `data-drop`)、シールド・墓地などは `zone:`(盤面の `data-zone`)のキーで、**直前の描画で測っておいた位置**(`fxRects.ts`)から取る。破壊されて消えたクリーチャーも、線の行き先・火花の位置が分かる。位置が分からないものは出さない。
- 攻撃・ブロック・シールドブレイクのバナーは、線を隠さないよう、盤面の上寄りに小さく出す。
- CPU の待ち(§4)には、攻撃の演出が終わるまでの長さを入れる(バナー・ゴーストとの大きいもの)。

#### 切り札(革命チェンジ・侵略)の入れ替わり

宣言のあと、次の3つが重なる。
1. バナー(上の表)。
2. 入れ替わりで手札に戻る札は、§2.1 のゴーストで手札へ飛ぶ(革命チェンジ)。
3. 出てきた札は、**上から落ちてきて**(`.trump-in`)、その位置に**金色の着弾**(`tone: 'trump'`。破片と輪)が出る。位置は攻撃後の描画(`fxRects` の `cur`)から取る。

### 2.4 決定的な見せ場(逆転の一手・切り札)

**S・トリガー / G・ストライク**(`triggerDeclared`)は、シールドから飛び出して試合をひっくり返しうるので、最も豪華にする(`FxLayer`)。
1. 画面が暗くなり(白い閃光)、盤面が揺れる(`.game.fx` の時だけ)。帯と見せ札の色は、S・トリガーが稲妻の黄、G・ストライクが白青、ラスト・シールドが赤。**回る光線などの装飾は付けない**(くどいため。方針 9)。
2. 宣言したカードが**見せ札**としてひっくり返って現れる(名前・文明・コスト・種類・パワー・テキスト)。効果を読めるよう、テキストをそのまま出す。ツインパクトは、S・トリガーとして使える面を出す。
3. 大きな「S・トリガー!」「G・ストライク!」(煽りの一言は付けない。方針 9)。
4. 見せ札に使ったカードの「呪文を唱えた」「召喚」の帯は、同じ手の中では出さない(重なるため)。
5. CPU の待ちに、この長さ(2.6 秒。高速は半分)が入る。**自分の分も出す**。

革命チェンジ・侵略・ダイレクトアタック・ラスト・シールドも同じ決定的な見せ方(暗転・揺れ)で、帯の色と文言だけが違う。

### 2.1 カードが離れた時(破壊・バウンス・捨てる・マナへ)

「何が破壊されたのか分からない」を避けるため、2つを同時に出す。

1. **ゴースト**(`FxGhosts`): 離れたカードの**元の位置**に、カードの影(名前・ラベル・文明の色)を出し、**行き先(墓地・手札・マナの `data-zone`)へ縮みながら飛ばす**。約 0.55 秒の一瞬の動き。破壊は赤く光る。元の位置は、直前の描画で測っておいた各カード(`data-uid`)の矩形から取る(新しい手が来た描画で、上書きする前の値を使う)。直前に描かれていなかったカード(進化の下のカードなど)は、ゴーストを出さない。行き先が見つからなければ、その場で縮んで消える。
2. **チップ**(`FxTicker`): 「破壊: A、B ほか2枚」のように、持ち主・種類ごとにまとめて名前を出す(名前は 3 つまで)。約 2 秒残る。

拾うイベントは `moved` のうち、場 → 墓地・手札・マナ・山札(ラベルは 破壊 / 手札に戻る / マナゾーンへ / 山札へ / 墓地へ)、マナ → 墓地(破壊)、手札 → 墓地(捨てる)。革命チェンジで手札に戻るクリーチャーも「手札に戻る」として出る。

**ブロック**: 「ブロック!」のバナーに加えて、ブロックしたクリーチャーが緑に光る(`.block-flash`)。バトルの結果、破壊されたクリーチャーは上のゴーストで墓地へ向かう。

CPU の待ち(§4)には、ゴースト(`GHOST_MS`)の長さを入れる(バナーの合計・攻撃の演出との大きいもの)。チップは待たせない。

### 2.2 軽い演出(ドロー・ステップの切り替わり)

画面の左上に小さなチップで積み、それぞれ自分のタイマーで自動的に消える(`FxTicker`)。**操作も CPU の進行も待たせない**ので、CPU の待ち時間(§4)には入れない。演出が無効なら出さない。

| 種類 | きっかけ | 表示 | 長さ |
|---|---|---|---|
| `draw` | `moved`(cause=draw) | 「ドロー ×N」「相手がドロー ×N」(プレイヤーごとに1手の分をまとめる。カード名は出さない) | 1100ms |
| `step` | 状態の `turn:active:step` が変わった時(最初の表示では出さない) | 「メイン / あなた」など。ドロー・マナ・メイン・攻撃・ターン終了 | 1200ms |

ステップのうち、engine がイベントにするのはターンの開始と終了だけなので、ステップの切り替わりは状態の差分から検知する。

その他の盤面の動き(`.game.fx` の時だけ): 攻撃を宣言したクリーチャーが相手のほうへ一歩前に出る。**手番のプレイヤーの盤面の縁取り**は、情報表示なので演出が無効でも残す。

### 2.3 選ばれない・攻撃されない状態(ジャストダイバーなど)の表示

ジャストダイバーで出たクリーチャーは、次のターンの開始まで「相手の効果で選ばれず、攻撃もされない」。これを演出ではなく**常時の情報表示**として出す(演出が無効でも残る。光のきらめきの動きだけが演出)。

- 判定は `wardOf(state, pid)`(`format.ts`)。`cannotBeChosen` / `cannotBeAttacked` の継続効果から作り、ジャストダイバーに限らず、同じ状態になる効果すべてに効く。ラベルは「選ばれない・攻撃されない」(両方)・「選ばれない」・「攻撃されない」。「触れない」のような言い換えは使わない(方針 9)。
- 札: **水色の光る縁**(`.card.ward`)・**🛡 だけ**の札(`.ward-tag`。文字は付けない)・ゆっくり流れるきらめき(演出が有効な時だけ)・本文に「JD」。選択中・攻撃対象の強調は、ward より優先する。
- ツールチップ・読み上げ: 「選ばれない・攻撃されない(持ち主の次のターンまで)」。
- カードの詳細: 「🛡 選ばれない(持ち主の次のターンまで)」「🛡 攻撃されない(…)」。

### 2.5 タップの向き

札のタップは `--rot` で表す。自分の盤面は**左(反時計回り 90°)**、相手の盤面(`.side-board.opp`)は**右(時計回り 90°)**に倒れる(依頼により確定。最初は両方とも時計回りだった)。演出のキーフレーム(`fx-pop` / `fx-block` / `fx-trump-in`)は `transform` を置き換えるので、回転(`rotate(var(--rot))`)を含めて、**演出中にタップが解けて見えない**ようにしている(テストで固定)。

## 3. 設定(演出: 通常・高速・オフ)

| 設定 | 内容 |
|---|---|
| 通常 | 上の演出を、記載の長さで出す |
| 高速 | 同じ演出を、長さを**半分**(約 2 倍の速さ)にして出す。CSS アニメーションの長さ(`--fx-scale: 0.5`)・バナー・チップ・ゴースト・CPU の待ちのすべてが半分になる |
| オフ | 演出を使わない(従来の表示)。バナー・チップ・ゴースト・CSS アニメーション・演出のための待ち時間のすべてが無効 |

- 「⚙ 表示」の **「演出」**(対戦中に切り替え可)と、対戦設定画面の同名の選択。同じ設定を共有する。
- 長さの倍率は `fxScale(mode)`(通常 1 / 高速 0.5 / オフ 0)。バナー・チップは作る時(`cuesOf(..., scale)` など)に長さへかけ、CSS は盤面のルートの `--fx-scale` を `calc()` でかける。
- 保存先: `localStorage` の `dmsim.fx`(`{"mode": "normal" | "fast" | "off"}`)。旧い保存(`{"enabled": boolean}`)は、true=通常・false=オフとして読む。対戦の設定・棋譜・自動保存には含めない(演出の設定で再現性が変わらないように)。
- 既定: 保存がなければ通常。ただし OS の「視覚効果を減らす」(`prefers-reduced-motion: reduce`)がオンならオフ。
- 「⏩ 一気に進める」中は、設定によらず演出を出さず待ち時間も 0。

## 4. CPU の待ち時間(`cpuWaitMs`)

```
fast                       → 0
間隔 = 人間と対戦中 ? max(速度, 300ms) : 速度
オフでない                 → max(間隔, 直前の手の fxHoldMs)   (バナーの合計・ゴースト・攻撃の演出の、長いもの。高速は半分)
それ以外                   → 間隔
```

演出が終わる前に、CPU が次の手で盤面を書き換えないようにするための待ちである。**待ち時間は「いつ打つか」だけを変える**。何を打つかは状態とシードだけで決まる。
